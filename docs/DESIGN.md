# 架构设计

## 1. 组成与依赖

应用是单进程本地研究服务。`app/main.py` 负责应用工厂与生命周期；`app/api/container.py` 是组合入口，创建并校验 Settings、DataHub、RepositoryBundle、DomainServiceBundle、调度器和扫描器的共享身份。

```text
HTTP / SSE / 静态页面                离线 tools/*.py
         ↓                               ↓
API 路由 → workflows → services ← 研究任务入口
                         ↓
              repositories / artifacts
                         ↓
                    db / models
                         ↓
                       utils
```

`models`、`utils`、`artifacts`、`db`、`repositories` 不得反向导入 `services`、`workflows` 或 `api`。跨层使用明确的领域模型、协议和仓储方法；禁止借助动态导入绕过约束。测试与生产都直接导入模型所属模块。`app/market_scan_repository_contracts.py` 是仍有现行消费者的扫描持久化适配出口；内部仍复用评分服务中的确定性回放实现。这是现有依赖边界的例外，不代表评分逻辑已完整迁入下层领域包；改变该边界需要同时迁移评分与仓储回放消费者。

`SQLiteCache` 聚合数据仓储。领域服务在组合入口构建并绑定为一个 `DomainServiceBundle`；缓存不再暴露重复的 `*_service` 快捷属性。保留 bundle 身份校验，确保被注入的调度器、DataHub 和容器不会混用不同数据库或服务实例。

## 2. 请求与资源生命周期

`get_datahub` 是异步 FastAPI 依赖，只读取已构造容器的服务实例，不占用 AnyIO 同步 worker。后台线程满载时，轻量扶摇缓存路由仍可完成依赖解析；真正的 SQLite 和文件工作继续在各自拥有的线程中执行。

| 所有者 | 负责 | 释放条件 |
| --- | --- | --- |
| FastAPI lifespan | 组合容器、后台服务、客户端 | 同时停止调度和扫描，清理工作台任务及 DataHub |
| RuntimeCoordinator | 同一 SQLite 路径的运行租约 | 调度器与扫描器均静止后释放 |
| MarketScanProbabilityRuntime | 概率研究预热、合并刷新、归档轮询及其锁、回调和实际I/O worker | 先停刷新，扫描收尾后处理归档并停止轮询，最后由扫描生命周期释放leader租约 |
| ProviderRuntime | 提供者准入、共享调用、超时及线程池 | 有界关闭；未停止的 SDK 工作结束后延迟清理 |
| DataHub 的 FuyaoService | 可选研究客户端、显式同步任务、侧库观察版本及请求预算 | 停止接收任务，收尾已有任务和文件 worker 后关闭客户端；不创建第二套行情运行时 |
| WorkbenchContextCache | 同股票/上下文共享构建，默认最多 4 个未完成构建任务，含缓存清理后存活的旧任务 | 请求身份隔离，取消等待者不错误终止共享任务；清空缓存仍保留活任务所有权，关闭后拒绝新读 |
| 浏览器控制器 | 当前页面读请求、轮询和 DOM 绑定 | 切换对象/隐藏页面/销毁时撤销或忽略过期读结果 |

同请求键共享 provider 调用，不同请求受能力队列限制。候选provider遍历只保留来源和冷却过滤，具体请求键由runtime最终准入统一判定；已有同步worker仍运行且可加入时，取消后的同键新等待者加入原任务，不启动重复抓取。不同键、正在取消收尾或仅余不可加入worker的情况仍受原背压。准入拥塞不是提供者故障；不能写成失败冷却。调用方取消不能强制结束同步 SDK 线程。关闭有界等待并保留运行租约，直到旧写任务真正结束；终态写入中取消优先于迟到的成功/失败。

调度器离线线程调用的等待必须保留真实 worker 所有权，不能将外层协程取消视为线程已终止。健康检查并行读取中任一子项失败或取消时，先等待其余子项实际结束，再原样传播异常。停止超时沿用延迟收尾与释锁；这不撤销线程已经完成的副作用。工作台命中缓存或复用当前同股票共享任务不占新额度，新构建超额时在启动前返回现有 503。清空缓存会移除共享键，但不能释放旧任务的运行额度，因此清理后同一股票的新构建也需重新准入。

调度器在本进程仍有手动任务持有执行资格时拒绝重新启动，直到任务真实结束后才进行孤儿记录恢复。RuntimeCoordinator区分已运行、显式禁用和暂时拒绝；暂拒不能报告激活成功，沿用服务回滚及静止后延迟释放租约，待命轮询再尝试接管。自动扫描预检作为至多一个受调度器管理的任务进入原活动任务集合，普通到期任务不等待预检；任务完成按身份清理指针，异常收割、有界停止、取消抵抗与延迟释锁复用原生命周期。

扫描管理器和查询服务使用构造时确定的同一份`MarketScanResearchStores`。`MarketScanProbabilityRuntime`显式接收仓储、研究stores、时钟、leader归属回调和脱敏值，不持有整个扫描管理器。管理器只在启动、发布和关闭阶段委托运行时，调度器仍通过既有公开方法维护研究索引。运行时自身拥有预热、刷新和归档任务，内部测试直接构造该对象，不通过拼装半初始化manager或替换私有store别名驱动生产兼容分支。

任务的自动窗口在`scheduler_schedule`统一计算，并在实际执行前再次检查；行情与研究任务核验上海可信交易日历，本地缓存清理采用20:00–次日09:00窗口。不在窗口内时更新下次时间，不创建“跳过但成功”的运行记录。不同任务的交易时段及盘后窗口见[运行手册](OPERATIONS.md)。失败和降级按连续次数退避，成功或待续复位、取消不计失败；该计数仅在进程内保存。手动执行沿用原单实例资格，不受自动窗口拦截。日历判定禁止自动联网补取，覆盖不足时明确暂缓。自动全市场扫描继续采用自己的调度合同。

健康检查与运行缓存清理为独立任务；后者在首轮维护间隔后才执行，并避让已有调度、扫描、扶摇及研究维护工作。仓储自动清理只有在独立快照和写事务内均无全市场批次候选时，才省略无关档案深验证；候选在两次检查之间出现则回滚，不能删除未验证的批次。有候选以及手动清理/预览仍完整验证研究档案与事务内原始字节。保留SQL窗口仅投影候选键和保护条件必要字段，避免大型JSON参与临时排序，保留语义不变。

调度状态展示通过现有`run_identities`取得最新扫描导航头，不调用会重新验证全批结果图的`latest_run`。展示的状态不授予发布或执行资格；真正的结果和策略读取仍经过完整封存校验。

SQLite、阻塞诊断和同步仓储工作不得占用 asyncio 事件循环。请求中的重验证使用有界准入；提供者线程池与 SQLite 工作分离。维护受时间间隔控制，普通只读请求不反复执行全库清理。用户数据导出、状态摘要及导入使用显式连接上下文，事务提交/回滚与物理连接关闭分别负责；连接创建后的初始化失败、正常返回及异常离开均关闭，不能依赖GC释放。

来源及历史概率投影不拥有冷验证线程。`ProbabilityResearchRefreshCoordinator`接收同步请求线程的刷新通知，最多保留一个后台任务和一个待处理通知，并通过生命周期代次拒绝旧回调。所有来源预热共享manager锁，取得资格后重读持久化archive bindings；仅完整稳定快照原子发布，文件/日期/绑定变化返回pending，隔离与概率展示准入不变。当前完整索引仍缺绑定来源时明确失败，不能把缺档永久隐藏在pending中。关闭撤销回调并等待实际预热、outbox审核及故障记录worker；取消不提前释放运行资格。

全市场普通及实验重验证读取的准入关闭受独立清理任务保护，复用 `await_cleanup` 抵抗重复取消，包括内部关闭子任务首次调度前的取消。关闭标记与任务注册使用同一锁；关闭后取得固定 worker 快照并等待，再显式幂等收割。不能对已完成但回调尚未执行的 worker 重复同步 gather，否则会阻塞事件循环。全部已拥有读取完成后才继续关闭 runtime、工作台与 DataHub，最终仍传播调用方取消。

本地导入由导入模块持有独立的提交请求身份；提交未完成时，新文件预览不能开放第二次提交。旧提交结束后仅释放自身身份，按当前有效预览恢复按钮，并在外层按钮任务收尾后再次同步。提交成功或失败使原预览失效时，按钮保持禁用；期间更换文件所得的新预览可以在旧提交结束后继续使用。服务端文件、模式、时间与令牌校验保持。

## 3. 时间与数据

共享 SQLite 连接的自定义函数注册和 PRAGMA 初始化属于连接所有者的清理范围。初始化、调用体异常及取消均先尝试回滚再关闭；提交失败不能返回成功。自选保存先取得 `BEGIN IMMEDIATE` 再读取需保留的字段，自选保存、更新、已读确认和计数调整都在原写事务内回读报价关联并构造返回模型，提交成功后才交付回执。内部回读/映射失败会撤销本次写入，不能留下失败后重试重复加计数的结果；网络响应丢失仍不是可自动判定的未写入。

- 市场日期、交易时段、行情事件按 `Asia/Shanghai` 解释；持久化审计时间为 UTC ISO 8601 `Z`。
- 进程内 TTL、冷却、节流、预算与耗时使用单调时钟；持久化行情缓存按 UTC 审计时间窗判断新鲜度，仍依赖可比较的墙钟时间。浏览器共享 JSON 缓存以请求成功完成时的 `performance.now()` 记录 TTL 起点，对外 `updatedAt` 仍为墙钟；显式失效清空独立的单调时点，不把有效的零时点当作失效值。
- 交易日历必须覆盖目标日期；缺失日历不能用自然日冒充交易日。
- 行情更新按市场事件时间排序；同时间优先非回退、字段完整、抓取时间较新的记录。
- 缺失指标与数值零分开表示；不把缺失财务数据、未成熟样本或未知预警写入状态解释为正常。
- 建议去重与未读计数在同一事务中更新。复盘计划采用修订号比较后写入，修订和评估尝试追加保存。

复盘结果字段和规范摘要由低层纯模块`app/utils/advice_review_evidence.py`唯一维护，仓储写入、回读验证和数据导入/ID重映射共同调用。仓储按SQLite存储原值生成摘要，导入显式按REAL列规范化浮点值；规范化策略不能隐式混用。版本准入仍属于调用边界：当前仓储只接纳v2，导入保留既有v1及历史未验证记录的限制。字段归一不改变旧摘要、SQL事务或计划修订载荷。

告警PATCH在仓储同一 `BEGIN IMMEDIATE` 事务内读取当前行、合并本次字段，涉及条件语义修改时验证类型与阈值组合，再更新及构建返回值；API预校验仅用于快速报错，不能替代最终事务内校验。纯条件验证属于models层，仓储不反向依赖服务。自选已读确认在原水位事务内将剩余未读限制为当前规范化未读数与水位后变化数的较小值；旧/重复确认只能保持或降低计数，后续真实变化仍由建议写事务增加。

笔记新增/修改的写入、内部回读及返回模型构建在同一事务内完成，提交成功后才返回；回读、映射或提交失败时整体回滚。成功回执后的独立列表请求仍是另一操作，不能反向撤销已确认写入。该边界不承诺网络断开后的端到端 exactly-once。

笔记列表/单条响应的 `revision` 是全部原始持久列及值类型的 SHA256 状态摘要。PATCH 要求 `expected_revision`，DELETE 要求同名查询参数；仓储在 `BEGIN IMMEDIATE` 内比较再执行，状态不同返回 409，缺失/非法前提 422，记录不存在 404。空 PATCH 同样检查前提。摘要不依赖墙钟唯一性、不落数据库，不表示历史修改次数；恢复后完整原始表示相同则仍相同，改变内容/身份/类型会冲突。单条 GET 使用 no-store，便于核对移出首页的笔记。旧页面或脚本须刷新或迁移：未携带令牌的 PATCH/DELETE 将返回 422，不提供无条件写入回退；现存数据库和导出格式无需迁移。

笔记编辑草稿与保存回执分开处理：列表重绘保留仍属于同一规范股票身份的打开表单，自己的成功回执仅推进所提交表单基线；后续新输入保留。409 后只读展示最新内容，须用户明确选择基于此版本继续或改用其内容，再手动保存，不能自动拿新令牌重试。写入成功后列表/图表失败仍报告已提交及读取降级。显式取消或切换编辑另一笔记沿用原表单关闭/reset语义；保证仍打开的草稿不被异步重绘清空，不保证页面关闭后的草稿持久化。

笔记创建仅在明确价格与非空日期、既有 30 天回退范围内本地精确且唯一股票身份可验证时，直接使用 StockInfo 保存而不请求报价。其余情况沿用报价填默认值的原路径；不接受客户端自造名称，不合成 Quote。外部行情不可用与本地服务不可用是不同状态。

笔记图表日期区分用户指定的交易日期与系统审计时点。显式交易日期按原市场日期格式取日；仅在缺省时才解析 `created_at`，将 UTC 或带偏移时间转为上海日期，历史无时区时间按上海解释。非法显式日期不回退到创建日，非法审计时间不生成日期；清空可选日期不改变 `visible`，隐藏笔记仍不输出标注。事件日期沿用原有解析合同。

Discovery研究入队在现有写事务内区分新来源与精确重复来源，来源身份为股票、扫描批次、方案ID和修订。精确重复只返回已保存的入队回执，不再upsert自选记录；用户随后修改的研究状态、备注及时间保持。首次或不同来源仍执行原入队晋级，包括保留holding_research的规则。来源写入和自选变化继续共同回滚。

“全部筛选结果入队”在单次收集开始时固定页大小，以重新读取的第一页确定页数；所有页须匹配已应用方案、修订、批次、规则及总量，收齐并核验跨页唯一性后才开始分批写入。窗口缩放不改变正在收集的分页规格，筛选替换取消旧读取，旧请求只清理自身状态。后续写入沿用每批100只的原事务与回执，不构成跨批次整体事务。

定时任务创建与重新启用在仓储同一 `BEGIN IMMEDIATE` 内核验源策略当前归档状态、所固定修订及指纹，再写入任务并构造回执。服务预检查不能替代此最终准入；允许固定仍有效的旧修订，不强制追随最新版本。归档先提交则启用失败，启用先提交仍按原归档行为处理，归档不会因此自动禁用此前已存在任务。停用不依赖源策略可读，管理操作本身不执行策略。定时执行取得执行权时还须在 `BEGIN IMMEDIATE` 内重新核验当前启用状态、源策略归档状态及固定版本绑定；停用或归档先提交则跳过，不新建运行记录，也不重启失败记录。已取得执行权的任务不因稍后停用被强制撤回，继续原有执行/完成流程；来源完整性与存储异常仍按既有契约传播。

数据库迁移必须在旧服务完全停止、备份验证通过的窗口进行。迁移事务先验证前置条件，最后写入标记；标记存在也不能跳过需要持续成立的完整性检查。旧格式读取只用于现有数据的审计与保守拒绝，不隐式升级来源或可信度。

公共数值与时间转换的快速路径只处理已证明等价的内置类型；数值子类和特殊转换保留原协议行为。市场 epoch 转换保持秒精度与上海时区，复现旧字符串往返对微秒及 DST fold 的处理；早年份和日期子类仍使用原格式化路径。性能优化不得改变输入接受范围、异常或数据时点。

日线窗口按独立日期计数，同日期的完全一致观测合并，存在行情、来源或执行元数据冲突则拒绝。提供者准入、缓存写入和评分使用同一重复值比较字段；冲突批次在写入前完整检查，不能通过数据库主键覆盖选择其中一条。缓存保存交易会话、开盘执行、公司行动、复权因子和 PIT 元数据，冷暖读取及评估投影不得丢失调用方提供的执行限制；旧库缺失字段保持未知，已有字段先验证原始类型，不能靠类型强转提升证据可信度。

分钟K线的新鲜度校验解析完整ISO时间，并将显式偏移转换为上海本地时间后判断交易日、交易阶段和未来边界；无偏移时间继续按上海时间解释。保留微秒，不截掉时区或非法后缀；越界时间拒绝。提供者返回与缓存读取共用该判定，原始时间文本、交易日历和新鲜度阈值保持。

分钟序列以完整时间对应的上海时刻排序，提供者与SQLite缓存均先排除无效观测、识别同一时刻的重复，再选取最近条数。缓存查询在指定股票和周期内执行，保留原始时间文本及微秒精度；同次输入的重复时刻保留最后有效观测，旧缓存的等价时间按获取审计时点和rowid稳定选择。分钟同键刷新使用替换写入，使相同获取时间下的连续刷新获得新的行序，避免换回原时间格式后读到旧别名。该表无被引用外键或不可变触发器。提供者失败时，在选取条数之前排除晚于当前时点的记录，明确标记合法旧缓存的降级。分钟维护使用同一时间键保留较新记录，原股票/周期分区和物理行数上限不变。分钟缓存数值列须为有效数值；不再将数值列中的BLOB字节当作合法价格或成交量，普通数值文本沿用SQLite列亲和性转换，公共数值转换工具保持原合同。查询结果有界，计算成本仍随目标分区大小增长；不修改日K同日冲突、写入或保留规则。

板块排行与分钟K线的缓存命中分别检查原新鲜度和请求覆盖。行数已满足请求时保持快速返回；较短结果只有在当前进程曾向同一来源链请求足够范围，且内容匹配、观测仍有效时才复用。短响应记录按来源名称/对象身份与顺序、业务字段摘要及请求范围绑定，以单调期限限制在原缓存TTL内，每个持有者最多保留256条；失效、容量淘汰或进程重启后可重新回源。来源确实只有较少行时不造数据；回源失败继续原显式降级。该记录不提升行情时间资格，也不等同于证明来源永远无更多数据。

股票搜索在主输入框和自选输入框的组合输入期间，将 Enter、上下方向键和 Escape 留给输入法；识别 `isComposing` 及兼容键码 229，不选择股票、不移动应用建议焦点或关闭建议。组合输入结束后继续原有键盘选择流程。

## 4. 个股研究

### 当前全景分的大盘、行业与可靠性

2026-09-14 第二轮修复后的工作台个股全景分使用 `current-stock-overview.v2` 聚合与 `current-market-context.v2` 上下文规则。技术面、量价热度（衍生）、基本面、事件面各占固定1/4方向预算：`E=50+Σ(可用方向因子分−50)/4`。缺失项提供0偏离，其份额不转移给其他项；重复或未注册的方向因子拒绝聚合。风险面使用 `aggregation_role=risk_constraint`，以 `P=max(0,50−风险面分)×0.25` 扣分，方向基分 `B=round(clip(E−P,0,100))`；无风险的50分不会通过均值抬高偏空方向。

响应分别提供 `directional_evidence_score=E`、`risk_penalty=P`、`directional_score=B` 及 `evidence_coverage_pct=参与方向因子数/4×100`。页面显示证据分→风险扣分→方向基分，并说明缺失份额不转移。覆盖只计四个方向槽位，不是字段完整率、上涨概率或统计独立性的证明，也不再次乘进可靠性。旧响应缺少新增字段时保留原显示；已保存的 v1 上下文只按原结果读取，不用 v2 重新解释或计算。

真实沪深300 `000300.SH` 报价与个股分析并行获取，每次工作台构建只请求一次，并沿用 DataHub 的缓存、合并和超时。指数不可用时仍返回个股分析。主行业从最多100项的完整行业页作唯一精确名称匹配，不把热门前20项未命中解释为股票没有行业，也不把近似名称或同名冲突当作可靠归属。

行业 `PlateItem.symbol` 保存东方财富原始 `BKxxxx` 指数身份，`quote_timestamp` 保存 `f124` 的真实行情事件时间，`updated_at` 仍为本地获取时间。秒 epoch 须为有限正值；缺失或非法时间不能补成今天。两个字段经过 SQLite 新表与兼容迁移完整保存/回读，旧行保持 NULL。板块请求仍使用有界单页和既有缓存覆盖判定，缓存命中不丢时间，也不靠每次强制刷新取得评分资格。

行业直连在传输失败时可切换到一个固定东方财富延迟入口，共享内部时间及响应体预算；结构不符不触发切换。延迟行情使用独立来源名，沿用当前评分的严格来源拒绝。直连Session已禁用环境代理，因此行业请求不再占用为其他SDK操作设置代理例外的进程全局锁；旧缓存回退的时间与过期规则保持。

准入要求沪深300身份正确、报价价格与涨跌幅自洽、来源非演示/非回退；行业当前仅接受东方财富直连的有效 BK 代码和唯一精确归属。上下文事件与个股报价须为上海同一交易日，不晚于个股事件或本次评估时点，落后个股事件最多300秒；行业另须满足事件时间不晚于获取时间、获取时间不晚于评估时点。解析完整时间及偏移，日期字符串不能代替行情时刻。这些是当前观察的对齐约束，不能证明历史行业成员或批次内完全同步。

市场 `ContextObservation.observed_at` 记录本次上下文已经取得该指数行情的评估时刻，即 `evaluated_at`，不是供应商逐字段首次发布时间或精确网络接收时间。行业该字段来自原 `updated_at` 获取记录。两者均不能自动提升为历史 PIT 可得性证据。

个股、行业、沪深300当日涨跌幅分别为 `r_s/r_i/r_m`（百分点）。行业有效时，`R=50+clip(5×(r_s−r_i),−50,50)`，`T=clip(B+0.2×((R−50)/50)×abs(B−50),0,100)`；行业缺失时 T=B，相对涨幅与R保持缺失。20%约束的是既有方向偏离的最大调整比例，不是与第二个方向分混合；无超额或 B=50 时不改变基分，连续保留原方向。响应的 `relative_adjustment` 保存实际 T−B，旧 v1 记录该字段可以缺失。市场约束 `g_m=clip(1+r_m/10,0.5,1)`；行业与市场都有效时 `g_i=clip(1+(r_i−r_m)/10,0.7,1)`。没有相应证据时该乘数为1，并保留缺失原因。上下文分 `C=50+min(T−50,0)+max(T−50,0)×g_m×g_i`；普涨不增加独立奖励，大盘/行业弱势只收缩正向偏离。

可靠性最后作用于偏离50的幅度：信号质量沿用 `round(0.7×信号证据分+0.3×数据质量)`，`q=min(信号质量,数据质量)/100`，全景总分为 `round(50+(C−50)×q)`。无上下文时同样将 B 向50收缩，不能把高数据质量直接加成看多分。信号证据分仍包含数据质量与技术方向清晰度的启发式组合，不是校准置信度。响应保存基分、可靠性、相对涨幅、中间分、两个乘数及来源/时间；前端显示实际采用和未采用的层。四份方向预算、风险扣分比例、0.2、每百分点5分、300秒和约束下界均为预先选择的工程参数，没有最优性或样本外收益改善证据。

风险面因子从中性50起算，复用风险规则但不传数据质量，只减价格风险级别与有效卖压惩罚，再按上述风险约束扣分；原分析风险等级和动作门禁继续保留质量约束。事件面从50起算，每条积极事件加8、风险事件减10并截断到0–100；没有可计分事件时该方向槽位不可用。按类别排除“行业”“数据”“观察”“异动”“历史复盘”，这些记录保留展示但不进入事件面方向聚合，避免把中性提示或重复价格证据变成看多奖励。该类别过滤不等于独立核实外部事实。

全景量价热度使用 `current-price-volume.v2`：`round(clip(50+clip(涨跌幅×5,−40,40)×clip(当前成交量/前5日均量,0.5,1.25),0,100))`。价格涨跌决定方向，相对量只调整幅度；成交额绝对规模和换手率不决定方向或可用性。必须为正式分析模式，报价须有完整事件时刻且换算上海时间不早于15:00，现价/前收盘价为有效正数、涨跌幅有限，报送值与价格重算值相差不超过既有0.3个百分点容差；通过后用价格重算涨幅决定方向，平盘误报、容差内符号反转不会产生相反方向，计算溢出拒绝。全部输入日K日期须为合法 ISO 日期、严格升序、不重复且不晚于报价日；基线严格取早于报价日的末5个样本，逐项要求有效 OHLC 与正有限成交量，不能跳过缺量再向前补足。同日报价正有限成交量优先，不可用时仅允许同日有效日K补量，同日K不进入均量分母。这是样本窗口检查，不另外证明连续交易日、复权单位一致或历史 PIT 资格。盘中、短样本或无效输入保持不可用50分，不形成可参与的方向证据。

量价窗口中的5日/10日连续性要求对应数量的独立日期及有效正收盘价，按 `round(50+30×(严格上涨段数−严格下跌段数)/(窗口长度−1))` 计算，平盘段不计方向；不足则50并明确缺证据。这些窗口只用于解释，不再次加入今日量价方向分。量价关系文案使用实际量比判断放量或不足，极高量比不会被旧量比分档误写成缩量。质量仍仅影响解释和最终可靠性，不直接改变上述量价方向。

因子实验室另将龙头强度标为 `aggregation_role=composite`：保留解释，当前权重为0，不与已经包含的趋势、量价和行业信息重复聚合，也不将复合观察计入独立校准因子数量。此变更不证明其余因子彼此统计独立。

当前分层结果明确 `historical_calibration_eligible=false`，不回填历史校准或改写已发布全市场 v5 评分。正式全市场尚未接入该上下文；生产升级须冻结旧规范构造器、在全池报价封存前采集统一上下文并绑定重放，详见[评分研究及下一阶段方案](SCORING_RISK_RESEARCH.md)。

### 行情估值准入

原行情估值路径至少需要一个有限非零 PE 或 PB；只有市值、零值或缺失字段时不产生有效估值分，历史价格位置也不能代替估值输入。市值仅作规模背景，不因规模较大直接加估值分。PE/PB 的估值历史和同行分位只使用不晚于当前行情时点的有效样本，未来或无法核实时点的样本不进入分位；排除后仍须满足原有样本门槛。该修正针对当前个股估值，不修改全市场冻结评分。

### 扶摇财务与市场观察

`FuyaoService` 由既有 DataHub 持有，REST 取数通过 `ProviderRuntime` 的研究能力复用请求合并、超时和失败冷却。客户端固定官方 HTTPS 基址和端点白名单，同时验证 HTTP/业务状态，不信任 HTTP 200 代表成功；同账号跨能力共享最小间隔及有界退避。`FuyaoPersistentBudget` 在每次尝试前，以独立侧库事务预占上海日期下的项目请求数，失败和重试同样计数。这个预算不证明供应商免费、账户余额或其他设备的调用量。

`Settings` 中扶摇默认关闭，Key 只来自受支持环境变量或显式密钥文件；文件延迟读取并检查普通文件、所有者、权限和长度，秘密字段不序列化。`tools/run_local.py` 仅为本地开发提供文件发现：存在项目 `data/fuyao-api-key` 时，为本次启动补充启用、密钥路径和已验证下载域名 `o.thsi.cn`，保留显式环境值。标准 Uvicorn 不执行此发现，页面不存在上传/保存凭据的接口。

`FuyaoResearchRepository` 位于 `cache_path.with_suffix('.fuyao') / 'research.sqlite3'`，保存追加的原始响应/规范观察、内容摘要、获取时间、任务回执和持久预算。财报采用独立 `FinancialReportBundle`，按证券身份、年报/季度及期间末对齐利润表、资产负债表、现金流量表与指标，不借 `Quote` 拼接财务字段。供应商报告日期与本地获取时间分别保留；缺数不补零，负值保留，金额及无显式单位的指标只显示原值和“单位待核实”。未核实金额单位、单季/累计、首次披露和修订历史前，不由三表推算 TTM、财务健康分或历史时点证明；供应商明确提供的 PE TTM 属于下述独立估值口径。

个股组装优先读取已有财报观察，已有市场体征在无财报或读取降级时仍可用。财务问答只开放已匹配的有限事实意图，并引用对应股票、期间和字段；不通过事实回答发出交易动作。估值的 PE TTM/MRQ、PB MRQ、PS TTM、PCF TTM 分开保存，分位只基于本地同口径观察日，不把当前快照补成供应商完整历史。行情与估值批次时间不冒充逐股/逐指标时间。

当前个股评分可采用已有扶摇估值观察中的 PE TTM 与 PB MRQ。准入核对股票身份、观察内容摘要及时间，拒绝未来记录和获取超过 7 日的观察；批次时间存在时也不得超过七日或晚于本地获取时间，不能重新获取旧值来刷新时效。至少一项须为有限非零值；脏类型或非有限数值导致观察拒绝，不能降为缺失后继续评分。七日是观察准入上限，不是逐指标更新保证或历史披露资格。通过后，一份评分结果同时供个股总览原“基本面”因子槽与估值分析使用，不叠加第二个估值因子，不混用行情历史或同行分位。

工作台在收齐研究输入后固定真实评估时间，一次读取扶摇本地评分。进入行情研究批次前还要求获取时间不晚于该批行情的时间戳，避免后到估值被标记成旧日期特征；七日窗口始终以真实评估时间计算，不能用旧行情延长有效期。研究批次的 `updated_at` 保持原时间合同，实际获取、评估时间和观察摘要单独披露。工作台上下文在现有缓存窗口内复用同一观察；更新扶摇缓存后，新建研究上下文才采用新观察，面板分别显示观察与评估时间。

评分沿用基本面槽的启发式阈值：基准 55；`0 < PE TTM < 25` 加 8，`PE TTM > 60` 或负值减 8；`0 < PB MRQ < 3` 加 6，`PB MRQ > 8` 或负值减 6；阈值等号不调整。负 PE/PB 分别保留亏损、负净资产的解释，不按“越小越便宜”加分。零值或缺失不贡献调整，也不按剩余指标重新归一化；两项均不可用时不能发布基准分作为有效评分。结果携带规则身份、来源、观察ID、摘要和评估时间。扶摇观察不可用时沿用原行情估值路径，并说明未采纳原因；页面读取和评分不因此触发远端请求。阈值不是论文估计参数，分数不代表财务健康概率或预期收益，依据与局限见[评分研究](SCORING_RISK_RESEARCH.md)。

`/api/fuyao/stock` 的 `value_research` 是当前本地缓存的价值研究摘要，采用独立 `value-research-v1` 模型并标明 `ranking_effect=none`。它复用本次已准入的 `valuation_score` 与财报记录，不额外请求供应商，也不写入工作台因子或旧行情研究批次。输入覆盖仅统计可用 PE TTM / PB MRQ 的 0/2、1/2、2/2，负倍数作为已覆盖的注意项；覆盖数不是置信度或完整价值分析覆盖率。仅对正值展示 `100 / PE TTM` 的盈利收益率及 `100 / PB MRQ` 的账面价值比，派生值须有限；这两项不是新增评分、预期收益、现金分配或清算价值。

价值摘要按页面选定的“期间末＋年度/季度”引用该期实际来源和获取时间，检查合并净利润 `net_profit`、经营现金流净额 `act_cash_flow_net`、所有者权益合计 `holder_equity_total` 的符号。报告期、完整观察时间、字段和来源表必须可核验且唯一；原始数值文本须有限且与规范数值一致，缺失、重复或异常输入保持不可用，正值也不推断财务健康。只有同一年度三张合并报表完整对齐时，才检查“净利润为正、经营现金流为负”的组合，提示核查营运资本及非现金损益；季度只作单字段观察。未知金额缩放不用于比率、现金转换率或目标价计算，旧报告期不描述为当前或 TTM 状态。

板块观察保存行业/概念目录、当前行情和显式选择的成员名单；当前成员不能进入历史成员回测。涨停/跌停/炸板逐页检查页数、总量、股票唯一性和采集一致性，同期龙虎榜另行验证交易日；异动解释只在支持的当日范围内保存，并标明供应商解释。没有返回的记录不解释为零风险，未来结果字段不进入当前特征。

`/api/fuyao/status`、`/stock`、`/market` 和 `/jobs/{id}` 均只访问本地记录并返回 no-store 响应；首次访问任务状态时会把上次进程遗留的活动任务标记为中断，不自动续传。远端同步仅由显式创建任务或补做任务触发。任务保存规范化请求、已完成股票和父任务身份；单项观察与对应进度在同一个侧库事务中提交，避免重启后记录已存在而任务仍显示未完成。

取消通过 `/jobs/{id}/cancel` 发出，先持久化 `cancelling`，后台停止后续取数并收尾已拥有的调用和写入，实际结束后才释放任务槽。重复取消不重复启动收尾；输出已经全部提交时，迟到取消等待原任务收尾并保留其完成结果。服务关闭即使无法保存停止意图，也必须停止并收尾已有工作后关闭客户端。`/jobs/{id}/retry` 创建子任务：财报和估值只保留原请求中尚未成功的股票，整批任务重用原参数；已保存观察保持不变。同一父任务的重复补做返回同一个子任务，即使该子任务已经结束；后续补做需针对该子任务。旧记录未保存请求时不能直接补做，也不从错误文本猜测参数。

浏览器明确区分未配置、无缓存、运行中、正在停止、部分完成和失败。任务回执不在最近列表时按ID核实，不能让旧回执永久占用页面；任务详情按用户操作读取。显式写操作独立于页面导航，读取结果仍校验对象与请求身份。报告期选择和市场筛选使用本地记录；重绘时按稳定键恢复市场面板展开状态。扶摇估值仅进入上述当前个股既有因子，不改变全市场评分、策略排序或券商执行；财报、板块和情绪事实不另行增加评分权重。

财报获取时间在本轮全部响应收齐后记录，供应商批次时间仍不得晚于该观察时间。无报表且指标为空或仅含 null/空白占位时不发布观察、不计成功股票，保留原缓存并允许补做；合法零值保留。

财报缓存读取在同一 SQLite 查询快照中按“期间末＋年度/季度”选取：优先该期最近一份含报表的观察，否则选最近一份有指标值的观察，不截断为最近100次同步。每一期保留整份观察内的事实，不从其他观察补齐缺表；最新部分报表可替换旧完整报表，季度请求附带的仅指标年报不能遮蔽已有年度报表。窗口排序只携带期间键和观察ID，选定后才提取规范报告，避免携带原始响应或重复宽记录排序。返回期间各自的来源和获取时间，完整性提示按最终期间重算；页面、财务体检与问答引用所选期的来源时间，旧格式缺省字段回退至所属报告包。

### 扶摇批量历史与研究导出

`fuyao_dumps` 在侧目录 `history/` 工作。全量请求十年日线签名，增量请求近十交易日日线签名，两者均另请求完整企业行动签名。实际文件通过独立无 Key 传输下载，限制为精确 HTTPS 域名和公网 DNS，拒绝跳转、压缩传输编码及超限内容；签名链接不进入日志或 manifest。REST 签名仍通过同一持久预算，文件下载不是额外的带 Key 数据接口请求。

pyarrow 按8192行分批读取，临时磁盘 SQLite 只用于校验、去重和归并，完成后不成为新运行时数据库。校验涵盖 schema、交易所代码、人民币、`1d/none`、上海零点日期、有限数值及 OHLC 范围。日线同证券同日异值拒绝；企业行动只删除所有规范字段完全相同的重复行，同日不同记录完整保留并标注事件/版本歧义，不相加或自动选择最后一条。除缩股对应的 `per_share_bonus > -1` 外，价格、金额和比例保持非负要求，且行动后总股数比例必须有限、为正。增量必须已有全量版本，先核验旧文件摘要，再合并新行并记录日线修订数。全市场日期以受信任日历检查连续性；个股缺席仍可能是停牌或来源覆盖不足，不据此制造停牌/可交易证据。

每个发布版本包含两份原始 Parquet、规范化 `daily.parquet`/`actions.parquet` 和绑定摘要的 manifest。文件先完整校验与落盘，再原子切换当前版本指针；失败保持旧发布，取消时等待文件 worker 结束后再清理暂存区。重读相同规范内容复用当前版本，较早版本不被原位重写。同步和 CLI 使用同一目录租约；普通状态读取只检查 manifest，显式 `verify` 才遍历所有摘要。

历史同步以线程安全的 `FuyaoSyncControl` 传递停止标记与阶段快照；下载及摘要按块、Parquet按8192行批次检查，磁盘归并也设有中断检查。后台任务节流保存真实阶段、当前量、已知总量和单位，未知总量保持为空，不计算虚构百分比。取消异常单独传播，不包装成损坏数据；文件线程退出后才清理暂存和租约。发布指针的短同步提交边界检查停止状态，已完成发布的版本保持可读。进度记录落盘失败在发布前触发受控停止；若数据已发布，则保持完成结果并明确提示进度保存失败，不能声称该数据没有发布。

`tools/sync_fuyao_history.py` 的 full/incremental 使用与服务相同的配置和持久预算；status/verify/export 可显式读取独立目录。研究导出包含未复权日线 CSV、企业行动 CSV、来源 manifest 和缺失证据列表，保持 `point_in_time_verified=false`、`official_execution_admitted=false`。未实现前复权转换、历史成分还原和正式执行来源准入，不能写入现有 qfq 缓存或作为评分晋级证明。磁盘容量与侧目录备份另行管理，主数据库备份不自动打包这些文件。

### 个股分析与交互合同

新增提醒和笔记在提交时记录股票、类型及阈值/内容。保存期间表单仍可编辑；成功回执只有在当前完整表单语义仍与原提交相同时才清空内容。相同文字或阈值但类型已经更改的草稿须保留，跨股票与改内容沿用请求所有者检查。写入成功和后续列表/图表刷新仍为独立阶段。

因子实验室“量价确认”的当前评分和历史代理评分共用 `research_volume_scoring.volume_confirmation_score`，与全景的“量价热度（衍生）”是不同规则。量价确认均以完整 20 日有效正成交量窗口的近 5/20 日量比为输入，按现行两位精度判断阈值。历史仅读取截至该日的窗口，缺量或无效窗口明确不可评分，由校准、分位和触发器排除，不能产生默认 50 分样本；PIT、执行证据与非重叠采样门槛继续生效。

工作台的报价、日线、分钟图、事件、财务、信号和问答分别由领域服务提供。`analysis_signal_*`、`financial_*`、`valuation_analysis` 和 `stock_event_*` 是实现入口，不保留只转发旧函数名的聚合模块。

普通交互加载是 `interactive_shadow`，不应写入正式建议历史。盘后研究队列使用完整交易时段及来源校验，要求收盘报价时间窗和至少 60 根有效完整日线。信号解释可以降级，但不能借缺失数据生成积极结论。

个股龙头特征使用 `feature-leader-v2`：量价热度的合法 0 分参与计算，只有 `None` 才使用中性默认 50，评分分量改善不能在零值边界造成综合分下降。共享加总算法和全市场纯趋势 profile 的含义不因这项修复改变。诊断证据充分度的周期冲突与风险收益扣分只在 0–100 范围截断，不能用正数最低分把低证据输入抬高；它仍是启发式评分，不是统计置信度或概率。

个股主动信号先执行既有硬异常阻断，再按数据质量总分降级；质量总分较高不能绕过该阻断。动作建议、买卖点、策略卡和做T助手使用同一判定；普通缓存或非硬性提示不新增阻断。趋势数值、风险等级、质量扣分及硬异常集合保持独立，规则匹配状态仅作为研究证据，不等于执行授权。

做T助手在两位发布精度核对低吸价严格低于现价、高抛价严格高于现价；越界、反序或舍入退化时两侧价位均待确认。资格使用ATR裁剪后的实际区间宽度，沿用 `max(1.2%, ATR% × 0.8)`，不让宽历史区间替代实际可执行空间。窄但有序的价位可供观察，不能生成执行步骤；style仍描述原历史区间。问答在做T资格未通过时沿用暂停步骤，不重新拼接低吸、高抛执行句。此判断仍是启发式区间要求，不代表已经核算真实账户交易成本。

Alpha 证据方向只采用明示状态：命中积极/风险保留原正负幅度，接近规则只有明确积极才有弱支持；观察、谨慎或未知不猜成正向。异动仅继承明确积极/风险方向。风险收益的正向支持须同时满足已登记评级及 `ratio_available=true`，有效“性价比一般”保留原弱支持；等待确认或未知为中性，风险评级的原负向幅度保持。

个股 ATR 使用有效日K末尾固定窗口的真实区间简单均值；有效的零区间仍计入分母，无效 OHLC 不补成零值。该实现保持两位输出和短样本的原有规则，不采用 Wilder 递归平滑；特征层仍要求至少 15 根有效日K才将 ATR14 标为可用。ATR 为 0 与缺少 ATR 证据分别处理。

日内区间派生盘口要求现价、高低价均有限且为正，并满足高价不低于低价。计算结果同时决定可用性与文案，不再由两套条件分别判定；缺失高低价不能生成买压或卖压。正数的有效单价区间仍可作为估计输入，真实盘口按独立的盘口证据路径处理，派生结果不会变成实测盘口。

研究问答通过有限整句意图匹配判断支持范围，再检查所需行情及研究证据。已有推荐问题保持可用，未识别的表达可按推荐问题重问。同行强弱要求有效比较样本，同行估值另复用 `peer_valuation_percentile` 的证据条件：当前有效正 PE 及至少 15 个有效同行 PE，不能用有行情替代有估值资料。响应显式包含 `answerability` 与 `missing_evidence`；不足或不支持时说明原因、不给交易动作并跳过 LLM，兼容的可靠度字段记为 0，不能将通用研究评分视为问题可答性的概率。

LLM 采用 `stock-qa-evidence-selection.v1`，只选择和排序本次服务端证据 ID，绑定合同版本、上下文摘要和原规则约束，不能提供自由事实文案。服务端按已有证据渲染，完整保留规则答案、动作和失效条件。未知 ID、重复 ID、错版本/摘要或附加自由字段均拒绝；一个总预算覆盖首次请求与至多一次纠正，失败回退确定性答案。证据选择不能证明上游来源本身正确。自然语言策略仍通过有限语法与约束编译，不将任意模型输出直接作为策略。

事件记录的 `evidence_kind` 区分实际事件 `event` 和空状态提示 `availability_notice`。默认“暂无高强度事件”仍可在事件面板显示，但不进入研究事件摘要的正、负或观察证据集合；摘要也不补默认观察句。三个集合皆空时，事件问答返回证据不足、无动作并跳过 LLM。真正的观察级行业、复盘和异动记录仍按研究摘要与问答的原规则展示和处理，但不因此取得全景事件面方向计分资格；缺少其他外部源继续明确披露。该分类标识不等于已核实来源事实，更不将行情推断变为公告证据。

个股概率请求只读取运行数据目录中的受检产物；研究样本在测试夹具中，不作为应用回退数据源。

## 5. 全市场与策略

策略目录为纯函数生成的静态研究模板，v2元数据记录模板修订日及当前维度、PIT、窗口合同，不查询数据库或声明样本数量；可载入只代表可编译。8个研究草案及其字段边界见[量化因子与策略](QUANT_FACTORS_AND_STRATEGIES.md)。原始特征硬过滤在候选上下文PIT复算后读取，并核对外层全部特征与证据负载一致；旧下行标准差不能作为当前半偏差。`strategy-metric-admission-v2-pit-raw-feature-bound`进入执行指纹，原有封存结果不回写。

定时策略过期提醒按交易会话计算：官方模式参考最近完成日K，盘中模式参考当前报价会话。事件记录参考日期、会话年龄和上限，日历不可核实则明确发出证据提醒。该当前时刻提醒不重解释旧历史执行在冻结决策时点的新鲜度语义。当前持仓权重须为有限0–1数且合计不超预算。

多维评分当前算法为 `full-market-dimensions-v5-target-semideviation`。主维度与影子研究共用 `return_risk`：最近 21 个完整收盘价形成 20 个简单日收益，零目标的平方负偏离除以全部收益数后开根，输出日百分点，不年化。上涨/零收益保留分母，非法价格拒绝；原 1%–5% 风险映射刻度和权重仍为启发式参数。旧维度 v4 按原负收益子集标准差重放，证据规范、外层算法及评分规范身份必须一致；不能将旧值重新标为新口径。生产趋势排序算式不变，但评分规范摘要因研究维度换代而变化。

当前影子规范登记同一下行偏差合同，新候选 ID 的摘要随之变化；当前重放拒绝旧候选规范。已有静态历史报告保留，不改登记或追溯重签。通用概率特征升至 v4、联合成交完整特征升至 v5，当前拟合与部署要求匹配的新输入口径；旧来源档案仍可审计，旧模型须重新拟合和验证，不能仅改版本标签。研究理由与兼容边界见 [评分风险研究](SCORING_RISK_RESEARCH.md)。

策略定时任务先构造全部提醒，再将提醒、运行完成记录和策略执行指针在同一 SQLite 事务内提交；任一写入失败整批回滚，不留下部分已发布提醒供重试重复产生。此前独立保存的执行审计草案可以留存，不能把提醒原子性表述为整次执行零写入。已完成运行不能再被失败回调覆盖；此边界不包含进程崩溃后的 `running` 任务自动恢复。

扫描分为市场池确认、报价批次、每股完整日线、确定性评分、结果持久化与封存发布。股票缺失与全链路故障分开处理；全链路故障保持待处理状态并进入有界恢复，不能把整批故障伪装成股票不符合条件。

TOP100快速更新只豁免全市场覆盖分母与全市场可评分比例要求，仍读取发布摘要，执行原快照采集耗时、观测跨度及信封完整性检查；不能以非全市场股票池为由绕过快照自身的准入。既有1200秒上限及评分规则身份保持，修复不追溯重判旧封存结果。

组合构建采用 `strategy-portfolio-allocation-v2-buy-cash-actual-minimum`，分配身份进入执行指纹。每单按参考金额加买入佣金、过户费及买入滑点估计约束现金，并同时受原单股金额、容量和组合剩余现金限制；按板块起买数量与步长取可负担的最大数量，取整后再次检查实际最低持仓金额。参考金额及买入成本按十进制、每单分精度结算；不能裁剪负余额掩盖超配。剩余现金只扣买入支出，卖出费用仍属于独立往返成本估计，未提前从本金扣除。这是纸面参考计划，不是券商真实成交；既有封存执行按原摘要只读，不重算或升级分配身份。

完整日线在 provider 清洗前检查请求窗口内的已完成交易日：损坏 OHLCV 触发单股数据错误并尝试备用来源，不能先删掉坏行再当作官方会话缺口。新扫描准入 `market-scan-input-admission-v5` 拒绝早于自身交易日收盘的显式快照时点，保留日期形式的历史粗粒度约定；新准入不重解释已封存扫描。 在既有完成快照价格校验阶段，official/preopen 报价昨收还必须与前一根有效日K收盘一致，沿用 0.02 元/0.5% 容差并只在边界处理浮点误差；冲突标为 missing，不推断复权修正。intraday 原昨收绑定、短样本与新上市 skip 顺序保持。该变更升级输入准入身份，不改变评分规格与哈希。 历史研究比较和来源采集仍依评分哈希及原发布合同准入，不因新扫描准入版本自动排除旧批次；旧数据可读不等于已按新价格规则重新验证。

当前基础评分为 `full-market-score-v5`。基础分与原始分一致，连续趋势贡献限于 `[-4,+4]`；展示百分位和舍入不改变语义。全市场趋势子算法为 `market-scan-trend-v4-scale-invariant-completed-snapshot`，计算用均线保留原精度，避免价格单位引入额外评分差异；规范摘要与批次身份随之变化。盘前仍使用已对齐的完整会话量价贡献，个股盘前/盘中缺少同进度量能时保持中性。旧趋势 v2/v3 保留各自的模式与两位均线计算，在冻结规范下回放；已登记的旧 v5 哈希可读，但新写入只接受当前哈希，不能给旧分数重标新身份。精确规格与摘要以代码和回放测试为准，文档不复制一份评分实现。

趋势上下文在每次构建时校验日线，并复用本次已校验收盘序列计算均线。共享当前趋势算法为 `trend-score-v3-scale-invariant`，计算精度与两位显示分离；新算法先将无量纲相对百分比稳定到 12 位，再将插值后的贡献幅度稳定到 10 位后整数化，避免浮点误差跨过半分阈值。这两种精度登记在评分规范 `rounding.trend_calculation` 中；旧算法保持原货币舍入及未量化的相对贡献算式。独立 `moving_average` 显示入口仍保留两位输出并校验输入；没有跨请求的可信序列缓存。缓存读取基准比较全部 Kline 字段的确定性摘要，摘要计算位于读取计时之外，避免只比较数量和日期范围漏掉行情或来源差异。

已发布扫描是不可变结果图。查询先校验封存身份、覆盖率与规则回放，再提供筛选、导出和策略快照。轻量轮询身份只决定是否重读，不能取得可信发布资格。批次进度不应触发没有变化的全图重复验证。

受检读取在同一只读事务中执行完整封存验证。publication 的结果时间上限由批次时间确定，每条结果的时间检查、严格 JSON 解码、规范摘要和评分观察共用一次结果遍历；时间检查先于下游观察器。评分合同只在完整摘要匹配且动作准入通过后发布，缺失、异构或计数不符保持不可用，不再单独全批聚合 JSON。封印写入仍先执行时间预检，旧 backfill 的审计语义保持。观察器局部状态不代表已获资格，不能跨请求缓存或提前构造受检会话。

冻结候选对比使用独立有界请求，接收2–4个规范证券身份和页面预期快照摘要。在同一`verified_market_scan_read`事务中验证摘要、批次与全部请求证券，最多读取一页4条冻结结果，再投影紧凑的分数、研究维度、行情字段和来源说明；不经过实时概率或当前个股覆盖层。对比结果的审计可读性与动作资格分别表达。浏览器对比集合独立于研究队列，跨同批次分页保留，批次身份变化即失效；请求代次与取消同时阻止旧结果，导出只使用当前已验证响应。

一次受检读取会话只读取一页仓储结果。启用概率排名时，该页按完整批次上限获取基础候选并保留；若后续发现研究维护不可用，回退使用这份基础候选的原 SQL 顺序，重新应用基础分区间及请求分页，不在同一会话再次读取。基础结果和概率排名分别复制构造，封存行不被修改。

概率榜单和维护降级的分页组装只序列化外壳元数据，排除将被当前页替代的全批 `items`；最终响应只序列化当前页。全批身份校验、概率投影、排序和筛选仍执行，不能通过提早截断股票池获得加速。返回页继续经过原页面模型验证，空页、总数和基础排序回退保持。

全市场执行研究的 `affordable_execution_purchase` 保留原最大毛额数量上界与货币舍入规则。在注册的非负费用下，总支出随合法数量单调不减；先试最高两档，再二分剩余合法手数区间，返回同时符合现金与成交容量的最大数量。最少数量不是步长整数倍时仍采用原步长倍数集合，不改成以最少数量为新网格起点。数量、费用、剩余现金和共享账户摘要均保持，搜索工作量不再随扣减手数线性增长。

公开保留清理在同一独占写事务内进行删除预览、必要备份与逻辑删除；借用连接的事务状态委托真实连接，封存删除仍保留原完整性校验和触发器恢复。结果模型在提交前构建，退出真实事务并恢复连接工厂后，才在维护锁内尝试可选压缩。压缩不持有缓存全局锁；达到原空闲页阈值才执行VACUUM，SQLite竞争或空间回收失败不否认已提交删除。删除或commit失败不进入压缩阶段，返回删除计数不代表保证磁盘已缩小。

历史批次导航按每页 100 条读取，不随翻页验证完整结果图；明确选中后仍核验批次身份再加载结果。成功响应才提交页码，失败保留原页，保留当前已校验的选中批次；筛选改变回到首页，清理导致越界时最多纠正读取一次。取消与往返切换模式必须恢复导航控件和已有任务跟踪。

筛选方案列表也按需分页，已选实体与当前列表页分开管理。另存条件创建新方案，更新则显式绑定已有 ID、修订和提交定义；写入确认与后续列表回读是两个阶段。多市场选项完整恢复；条件无法在表单中无损表达的方案继续按保存定义应用，不允许静默丢弃条件后覆盖。

方案列表的总数与分页条目使用同一SQLite只读快照；并发新增或删除不会让同一响应混合提交前后的数据。下一次请求可以看到新提交，普通列表翻页不承诺跨请求冻结全部方案。

筛选关键词统一归一化普通空白，并拒绝剩余控制字符，防止 SQLite 字符串终止语义与 Python 解释器查找语义不一致。GET 榜单和 POST 筛选解释均在执行前以 422 拒绝非法关键词；正常文字和字面通配符语义保持一致。

筛选评估使用`market-scan-screen-evaluation-v2`。一次`verified_market_scan_read`会话内读取全批标量投影、计算失败集合，再一次有界读取当前命中页和近失详情，保留最大200+100条。顺序漏斗和独立条件影响复用同一失败集合；每个条件仅统计失败集合恰好只有该条件的行，并分别累计原值缺失数。示例最多3条，按同一筛选排序从标量投影取得，不扩大详情水合或逐条件重复扫描数据库。所有计数来自完整冻结总体，与页面和近失条数无关。

浏览器单独保存已成功应用的筛选上下文：标准榜单绑定真正发出的查询及受检响应，方案榜单绑定完整保存定义和修订。工作台按此上下文读取，不从当前表单草稿推断条件；返回的完整批次及规范化规则须一致。加载、失败和切换使旧解释失效，空结果入口只打开工作台。概率阈值或v6生产重排暂不能由基础冻结解释器精确表达时明确拒绝评估，不静默忽略或补算。该限制不阻止独立的市场宽度与批次变化展示。

普通榜单与方案榜单共用表格读取所有权。真正开始读取时取得身份，提交及失败处理均检查身份，避免一个入口的迟到结果覆盖另一入口。方案持有当前批次时，普通榜单后台刷新保留轻量批次轮询，不重新占用表格；显式普通查询或换批次才移交。未变化的身份轮询不能清空仍在展示的筛选解释，释放页面结果时同时作废方案在途读取；保存和批量写入仍有独立生命周期。

筛选变化历史从 `discovery_screen_alert_event` 直接读取已保存集合，使用摘要列表与单事件分类明细两级分页。读取不重新执行筛选或查询在线数据。事件标识、方案 ID/修订、前后批次与原摘要共同提供历史定位；旧记录没有保存历史名称和完整条件，不由当前方案补造。原摘要按存储值保留，不宣称可在缺少旧条件时重新认证。返回前验证 JSON、证券身份、互斥集合和计数，损坏记录返回错误。前端读取按方案和事件身份隔离，隐藏或切换时取消旧读取；已确认的记录写入独立保留。

概率数值层由 `market_scan_probability_estimators.py` 拥有 Logistic/Newton、Platt、PAV、分箱预测及对应版本和收敛异常；`market_scan_probability_values.py` 统一严格值校验和回放异常。估计器仅依赖只读配置/样本协议，不导入概率编排。主概率模块负责样本分区、拟合流程、证据及公开预测准入；实验、联合执行和研究消费者直接导入数值所属模块。模块提取不改变运算顺序、已登记版本或证据摘要。

研究概率、未来区间和执行 Shadow 绑定同一来源、信号日期、交易日历及样本定义。分开验证原始数据、可执行价格、成本、样本外表现与独立控制授权。历史格式可保守读取，不允许自动升级至正式排名或交易结论。离线工具和人工控制均不得偷偷替代发布证据。

v6 概率排名采用独立版本的推断合同，区别于保留原值的 v6 分数变换。当前固定 v5/v6 比较缺少完整冻结搜索族、试验基准与时间依赖推断，以及共享资金的日频 NAV；DSR、PBO、真实组合回撤明确不可用，当前不能授权新的 v6 晋级。零基准 IID PSR 和重叠持有期超额收益链仅为诊断，独立会话计数改称不同会话数量。新合同记录真实变更时点，不能给新规则套用旧登记日期；旧 shadow/control/发表按原合同审计，旧控制不能产生新发表，已冻结结果和回滚保持。恢复晋级须另行提供合格研究证据，不能把连续分块反例、换标签或人工确认作为统计证据。

概率 outcome 的 `qfq-daily-fixed-session-bar-evidence-v2` 保存标签实际读取的会话状态和开盘执行状态，生成与回放使用同一证据。旧 v1 丢失这些字段，必须先验证其原始结构、摘要和旧语义，再报告语义漂移并交由维护流程处理，不能静默补字段后当作当前研究。损坏旧产物仍按完整性错误拒绝。

固定会话标签使用 `market-scan-upside-label-v4-execution-phase-separated`，前向评估与比较报告升级至 v4。共享日线成交判断显式接收 `open` 或 `close`，默认仍是开盘：收盘退出不继承只描述开盘的锁板/不可用状态，但停牌、零量、一字板、容量和来源限制仍生效，日线模拟仍标识 `model_limited`。旧 v2/v3 标签先按旧执行语义完整校验记录、摘要和质量，再报告 `ProbabilityOutcomeSemanticDriftError`，不能作为当前训练证据；损坏记录不能借语义漂移绕过完整性检查。

个股 compact assessment 使用独立的代理收益目标 v1，并未采用上述成交状态模型。旧 assessment v2 只接受精确登记的旧估计器标签元数据 v3；当前 assessment v4 要求当前特征合同，可验证已登记的旧 v3 或当前 v4 标签元数据，其余目标、配置和切分字段仍须严格相等。新构建记录实际使用的共享估计器版本，旧文件按原字节读取；读取旧元数据不使历史诊断取得当前概率资格。source-v3 归档容器内，旧 feature-v3 只能绑定已登记的旧评分摘要，当前 feature-v4 必须绑定当前可写评分摘要；读取旧档案不授予当前拟合或来源采集资格。

历史重放产物升级为 `market-scan-probability-historical-replay-artifact-v2`，其 `probability_fit.estimator_binding` 明确绑定独立历史收益标签、共享估计器版本及各持有期配置摘要。旧 artifact-v1 在信封及摘要核验后以 `HistoricalReplayFitContractSupersededError` / `superseded-fit-contract` 明确拒绝，需从原始输入重新生成；这不表示旧拟合已经深度回放通过。新 v2 不允许旧切分版本绕过拟合重建，也不能将缺少绑定的旧报告直接重签为新产物。

未来区间研究 `fixed-session-future-range-v3-execution-phase-separated` 保持价格区间与执行标签各自的准入规则，执行模型区分下一会话开盘入场与固定会话收盘退出。使用的会话与开盘执行元数据进入产物摘要；类型非法时只将执行结果标为不可用，不能把全天锁板或停牌当作普通成交。旧 v1/v2 冻结文件保持原内容，不改写或自动提升为 v3 研究证据。

模拟交易 `paper-review-plan-v3` 按开盘退出、开盘买入、盘中／收盘退出、收盘估值执行。只有已经在开盘实现的卖出资金可支付当天开盘买单；新买入仓位的触障信号锁定至后续可卖会话。已知开盘跳空先于之后的高低价，只有无法区分的盘中双触障才保守止损。锁板延期退出仍使用有效交易日收盘估值，暂停或无有效价格不生成新估值。执行约定进入运行指纹，历史运行保存原版本。

所有模拟卖出在统一提交点检查可用现金加卖出所得能否按货币精度支付完整费用。费用不足记录 `exit_fee_cash_shortfall`，保留持仓、首次退出原因及日期，按原顺序在下一可卖会话开盘重试；未成交不扣费，不把负现金夹成零。新 `exit_cash` 执行约定进入配置与输入指纹，旧运行保持原配置、摘要及读回内容。该约束保护实际现金，压力配置下包含完整预计退出费的清算净权益仍可能为负，不把两者混为一谈。

共享现金模拟以可信交易日历推进至请求的完整行情截止日；通过初始准备后，仍待入场或持仓中的策略必须提供当天会话证据。缺失时整体拒绝本次计算，沿用业务错误 400，旧运行、账户表和策略状态均不写入。激活后尚无应有交易会话时保持等待，已有应有会话但完全没有初始行情时保留 `data_unavailable`。明确停牌与已结束策略按原规则处理。基准必须覆盖账户所需会话，只有明确停牌才允许延续前收，否则整次比较标为不可用，基准收益及超额收益返回 null，账户自身收益仍可计算。两项覆盖策略作为固定配置语义进入运行指纹，没有关闭门禁的用户开关。

保留策略模板、实验模型和旧来源读取的前提是存在当前 UI、CLI 或持久化审计消费者。仅因名称含旧版本号不能判定代码无用。

策略定时任务管理按需展开，使用现有列表与启停服务，保持策略 ID、固定版本和指纹绑定。管理面板拥有独立读取序号，切换载入策略使旧响应失效；分页成功后才更新页码。启停提交不随页面读取取消，不自动重试结果未知的写入；有效回执和后续同步分开呈现。读取面板不调用自动执行入口。

### 冻结评分的后续跟踪

`market_scan_evaluation.evaluate_market_scan_score_tracking` 保留公开导出，实际编排归属 `market_scan_score_tracking`：在一个只读 SQLite 快照中选择最早扫描、校验封存并读取有界后续日线，不调用提供者或完整概率拟合。评估与跟踪通过 `market_scan_evaluation_source` 的公共函数共用只读连接与冻结证据解析。跟踪以版本身份隔离样本，在读取收益前固定高低分组，计算同日配对的日期等权差值；缺失日期不会从重采样时间轴删除。`track_market_scan_scores.py` 使用已有原子独占文件发布机制输出摘要命名的 JSON 和静态 HTML。此入口独立于线上页面请求与模型发布，不增加打开工作台的计算负担。具体比较和证据边界见[评分跟踪](SCORE_TRACKING.md)。

`strategy_template_tracking` 在独立只读事务中校验最早正式全市场批次的原始封存、完整成员、评分合同与时点证据，复用纯函数 `build_portfolio_draft` 冻结三模板组合，再关联后续结果。`strategy-template-tracking-v2`保留根节点D至D+H毛收益，并新增`net_comparison`与`strategy_selection`，避免将信号收盘价格回看当成可成交净收益。可选`--non-overlapping-signals`在后续日线读取前，按每合同首日和可信日历每H+1会话固定批次；与`--run-id`互斥，首批失败不补位。

`strategy_template_net_returns`绑定冻结模板成本和严格加载器返回的`VerifiedOfficialExecutionSession`，`strategy_template_net_execution`按D+1开盘入场、D+H+1收盘退出计算独立现金预算。CLI的注册表、独立摘要、原始文件目录与会话目录四个官方参数须完整提供，验证失败不能降级为合格输入。净执行使用未复权价格重新求可负担数量，遵守整手、费用和滞后容量；压力情景把佣金率及最低佣金乘1.5，双边滑点各加10bp并重新求数量。明确未成交保留现金，路径未知或退出受阻使整篮不可用；净执行的`residual_cash_cny`为退出后的期末现金。`strategy_template_tracking_metrics`仍只负责毛收益，毛收益空篮与净执行无交易现金情景分别处理。

`strategy_template_selection`按每合同完整日历固定H+1间隔锚点，失败日期参与范围界定，任一成熟锚点不完整就阻断推断。至少20个完整锚点后，使用2000次、块长2锚点、三模板同步的循环移动块bootstrap，再对三对双侧检验进行Holm校正。统计赢家须分别优于两个对手；压力均值优势及最差独立批次回撤不恶化超过2个百分点另行检查。批次回撤来自收盘估值，不是连续资金账户NAV。数值门槛是工程合同，不是充分统计功效保证。

CLI独立生成内容寻址的JSON和HTML，不保存策略或执行、不进入生产排名或模型晋级。回溯比较的诊断领先、统计优势、压力/风险通过和采用资格分别输出；`adoptable_template_id`始终为`null`，不覆盖用户策略，原因包括缺独立前瞻验证及连续资金/持仓验证。旧报告缺少新对象时明确显示尚未生成净收益选择结论。具体边界见[策略模板对照](STRATEGY_TEMPLATE_TRACKING.md)。策略编辑器分别维护持有交易日和调仓间隔；再次编辑不得将已保存的10/5规格改成10/10，缺失间隔需补充后编译；计划间隔不表示已实现自动调仓。

## 6. 文件产物与本地数据

`app/artifacts/io.py` 统一有界文件读取、严格 JSON、内容摘要及原子写入。产物以内容身份持久化，拒绝路径逃逸、符号链接替换、非有限数和不完整依赖。仓储拥有 SQLite 事务与结果图删除；服务通过公开契约访问。

运行时备份使用 SQLite backup API，并验证完整性、外键和清单摘要。它不自动打包研究侧文件；恢复前必须检查对应目录，防止旧数据库与新产物组合。数据导入先 dry-run，提交绑定精确文件、模式及目标状态，不能导入后伪造来源可信度。

预警流身份持久化在独立的 `alert_stream_state` 单行表，记录随机 `stream_id` 与本代起点。正常初始化只补建完全缺失的旧表；已有结构、行或取值不合法时拒绝读取，不生成新身份掩盖损坏。事件高水位取现存最大ID与SQLite自增序列的较大值，清理全部事件也不能使它倒退。成功恢复与replace导入均在安装新历史时换代，以该历史高水位为起点；普通重启、merge、dry-run和保留清理不换代。该协调元数据不进入用户数据导出。

恢复先按原清单验证原备份字节，再在私有暂存副本内用SQLite authorizer限制通知元数据写入；旧库缺表时仅允许建立精确的元数据结构。业务UPDATE、额外DDL、ATTACH与写PRAGMA等均不获授权。独立回读新身份并复核完整性、外键、封存和允许变化的事实后，才生成内存派生清单，对原子替换前后再次验证。原备份保持原字节；安装后验证失败按原目标的一致性回滚快照字节精确恢复，不给回滚库再次换代，不等同于保留活跃WAL主文件的原物理布局。

保留窗口只删除无引用且完整性验证通过的扫描图；当前任务、重试祖先链及真实产物引用均可固定旧图。摘要是身份信息，不是数据备份。

## 7. 前端

页面恢复先建立最终主区，再恢复其子页，避免自选页记忆的财务或模拟页触发隐藏读取。股票工作台归研究和复盘所有；系统与自选切入时撤销旧股票读身份，切回通过微任务再次检查页面、延迟状态和在途请求，保证显式导航优先且只恢复一次。全局读取按主区分流，系统保留数据状态及可见诊断，自选保留观察列表和报价。报价订阅独立判断可见主区，自选不依赖个股分析成功；完整自选读取在共享读取路径建立就绪状态，局部写回与旧缓存不冒充完整成功快照。线上恢复在非股票页只刷新当前全局数据，不重选隐藏的失败股票；导入后的刷新回执按当前页面判断。

研究历史仍由既有成功工作台渲染路径记录，启动只读取其校验后的首条，无新增存储格式；清空历史同时取消下次启动的股票恢复。高级概率研究用原生details折叠，子面板ID和控制器保持，折叠不重置周期、实验开关或证据。

运行状态的监控和诊断请求仅在“系统维护 → 运行状态”可见时加载；退出或页面隐藏时取消读取和轮询，已排队的旧定时器不能复活。显式启动的后台任务写请求仍独立完成。数据管理先读取轻量扶摇摘要，“检查可清理数据”按钮才启动研究文件完整性预览，执行清理仍重新核验。扶摇三个 GET 统一使用12秒读取预算，首次加载和超时均有提示，失败保留已显示的财报、市场和任务内容。

静态 HTML 直接加载分域 CSS；`static/app.js` 装配主工作台，布局与筛选增强另有两个模块入口。具体状态、控制器和行为放在 `static/js/`。`advice-review-events.js`、`stock-note-alert-events.js` 独立拥有相应事件绑定和释放；`stock-panel-requests.js` 统一笔记/预警的请求生命周期。

报价流由`quote-stream-controller.js`闭包持有EventSource、重连计时器与连接代次；订阅证券规范和帧验证属于`quote-stream-contracts.js`。工作台只注入当前上下文、连接条件与展示回调，不保存可变连接对象。切换、隐藏、pagehide和销毁由已有页面生命周期委托控制器；旧帧和已取消计时器即使迟到，也须通过当前连接与上下文身份检查。只读诊断快照不暴露连接对象或可写状态。

功能入口按操作对象划分：个股研究包含笔记预警，全市场选股包含策略实验室，复盘模拟管理计划与账户，自选监控管理关注队列与观察，系统维护管理全局运行状态与本地数据。页面仍使用唯一既有控制器和写入路径。笔记页显示当前股票上下文，并隐藏重复图表；全局模拟账户隐藏个股查询，避免误以为切换股票会筛选账户；主区切换恢复各自子页。浏览器偏好 v2 仅保存白名单视图与图表选项，按实际归属迁移 v1 的笔记／数据入口，不保存股票数据、草稿或凭证。

股票切换取消读请求并阻止过期 A→B→A 响应覆盖当前界面。已发出的用户写请求有独立生命周期，不能因导航而撤销服务端提交。写后回读只更新仍匹配的对象；失败保留草稿。笔记、策略与复盘计划收到有效成功回执后先固定本地确认身份，后续读取失败单独显示，不把已完成的写入重新报为失败。已知部分笔记不当作完整列表，只有成功读取空数组才能显示暂无。重复绑定同一根节点不得叠加监听器；可复用既有绑定，需要更换绑定上下文时先释放旧监听器再绑定，避免一次点击多次提交。

预警规则编辑由领域草稿模块管理提交与打开代次。有效保存回执只关闭原提交仍未变化的表单；等待期间新输入、另一规则编辑或取消重开的新编辑继续保留。列表重绘仅在规则ID、股票和创建身份一致时复用打开的编辑DOM，保留草稿、焦点及提交按钮占用，并同步最新服务端字段作为取消编辑的重置基线；记录删除或身份替换不继承旧编辑。写入成功与独立回读失败分别呈现，当前保存失败保留输入供重试。

问答接受结果与结束忙碌状态使用不同条件。被取消、过期或属于旧股票的回答不得回写；结束时仅释放仍属于该请求的原表单。刷新失败保留原 DOM 时，问答按钮应恢复，允许再次提交；旧请求结束不得清除新请求的忙碌状态，也不得操作已替换的表单。

图表范围切换使用已有日线数据；分钟周期、复盘记录与概率面板各有独立请求身份。折叠面板不应预取重研究结果。CSS、键盘焦点、ARIA 和移动端布局通过真实浏览器回归验证。

图表横轴将有效的完整时间戳转换为上海市场时间，不随浏览器时区变化；日线的交易日期按字面日期显示。图表检查器继续保留来源时间的完整原文，显示转换不改写行情对象或获取时间证据。

自选筛选使用完整队列的本地投影，不替换 `state.watchlist` 或改变后台活跃池。搜索与筛选只切换既有行的可见性，保留正在编辑的 DOM 和读取失败提示；日期筛选与复核徽章使用上海日期。筛选条件属于当前页面会话，未读变化不会因筛选或普通打开图表而被标记已读。显式查看变化使用独立导航入口；股票、加载序列、可见记录和读取水位同时匹配后，定位时间线并提交原有标记已读事务。离开页面或行情／时间线失败保持未读。

策略编辑草稿与已保存策略分别拥有身份。任何输入立即失效执行资格；编译结果绑定输入、请求序列与控制器生命周期。执行等行动只接受已归一化且与已保存指纹和内容一致的草案，保存回执还须对应发出的草稿和原版本。保存期间的新输入不能被旧回执覆盖。纸面委托草案仅渲染现有计划结果及来源身份，与复盘账户的撮合和持仓明确区分。

策略列表和执行历史按已有服务端分页读取，页大小100，页码与列表仅在响应通过身份/计数校验后提交。当前载入或刚确认的策略可作为独立选项保留，明确标注不在本页，不计入分页数量。分页失败保留原成功页，历史列表绑定当前策略；打开指定历史执行先核验执行、策略版本、来源及成本指纹，再独立读取候选页和已有纸面委托。没有计划与计划读取失败分别表示，失败可通过重新查看重试。恢复仅改变执行展示，不替换编辑草案，不调用执行或计划创建接口，恢复的执行不取得纸面计划创建权限。

模拟账户初始资金锁定依据账户中的策略与历史运行，包含空运行；锁定后配置请求仅提交默认成本。账户修改在首次读取前取得SQLite写事务，历史准入检查、资金/成本更新和返回模型构造共同提交；另一连接先保存历史时拒绝改资金，模型或提交失败回滚全部更新。账户更新先取得写事务时，其它写者等待；此前已准备的模拟草案仍保留自己的冻结配置，不追随当前账户重算。历史策略的删除资格依据是否进入不可变运行，而非是否持仓或当前结果状态，后端仍保留最终约束。

模拟策略创建的最终计划准入、插入和返回模型构造在已有同一写事务中完成。内部回执构造或提交失败时回滚新策略，同一计划版本仍可重试；成功回执与持久化记录一致。此边界覆盖服务端提交前的内部失败，网络中断后的未知提交结果仍须按原流程核对。

模拟运行对比有独立可取消读取范围，并绑定看板操作代次及左右运行选择。新看板操作、刷新、重新对比或任一选择变化使旧对比失效；选择改回原值也不恢复旧请求资格。过期成功、失败和清理不得覆盖新反馈或新请求。已完成的对比沿用原展示方式，账户和模拟写入独立于该读取范围。

全局复盘导航传递股票身份及具体计划 ID，单计划读取与常规历史分页分别管理。目标响应须匹配最新选择及对应股票，已定位计划与普通分页按计划 ID 去重；定位不改变分页偏移、计划修订或评估状态。行情加载失败时，保留原有行情回退规则，只读展示明确标注股票身份的本地冻结计划；不赋予编辑、评估或归档资格。成功修订或归档使该计划在途的旧定位读取失效。

到期队列使用独立的按需分页读取，不与普通计划列表按ID拼接。`GET /api/reviews/due` 返回 `items/total/page/page_size/page_count/as_of/snapshot_token`；股票代码子串、快照起始日和观察周期在服务端先筛选再分页，按到期日、计划ID排序。仓储在同一SQLite只读事务中校验活动计划与最新评估，再用内置交易日历判断成熟和逾期。`as_of` 为上海市场本地时间，按已发布日线截止时点稳定化；它是到期判断的截止时间，不是历史数据库状态回放。跨页摘要绑定规范化筛选、截止时点、页大小及完整筛选结果；后续页必须携带原截止时间和摘要，内容变化返回409，不能只凭相同计划修订号认为评估未变。分页限制响应和DOM数量，当前仓储仍读取全部活动计划进行验证，不保证数据库成本与页大小成正比。

普通看板读取全局统计和常规完整计划列表，纸面交易继续使用后者。“已到期”模式另按50条一页读取，页码只在成功后更新；翻页失败保留成功页，重试原目标页，409提示重新读取第一页。筛选变化重建分页身份，旧响应不能覆盖新筛选；读取失败不能展示为“无匹配”。全局统计和每次最多100条的批量到期评估不受当前筛选、页码影响；筛选与翻页本身没有评估或保存副作用。

复盘表单将编辑代次与原始字段值绑定到发出的保存请求。服务端回执先确认该计划的新修订；仅当前表单仍是提交时的同一代次且字段未变时按原流程重置。改为编辑另一计划、显式取消再开或有新输入时保留当前草稿及有意空白；同一计划的新草稿只推进已确认的修订基线。请求结束后按当前表单恢复按钮文案和可用性，避免通用提交包装器恢复过期状态。独立列表回读不能重新覆盖保留的草稿。新建成功立即保留已确认计划，并仅在紧随该提交的有效读回请求内合并确认项；普通后续刷新仍可移除已归档项目，不建立永久保留的列表副本。当前工作区的提交占用独立身份，编辑期间不重复发出写入，旧工作区请求结束不释放新请求。普通分页偏移只按成功读取的原始页长度推进；额外展示的确认项和定位项不增加偏移，归档已读取条目才扣减对应位置，切换股票重建水位。

复盘追加分页失败保留已验证列表及现有DOM，不清除编辑草稿或已有提交反馈；分页旁提供独立状态和原按钮重试。只有成功读取才推进普通分页偏移；重试复用失败页的位置并去重。正常刷新或股票归属变化清理旧分页错误，取消及迟到失败不污染新页面。普通列表和精确计划定位的读取可独立完成；列表重绘前仅捕获当前焦点正位于该列表卡片本身的计划ID，重绘后同一卡片仍存在才恢复焦点，不再次发起滚动。用户已移至输入框或其它控件、卡片已消失时不抢焦点。

行情SSE周期性传递当前快照，断开后重新读取当前行情，不提供逐条历史报价重放。预警通知使用独立的 `GET /api/alerts/notification-events`：游标由流身份与事件ID共同组成，身份、高水位和升序事件页来自同一只读事务快照。没有游标的首次读取只建立当前高水位，不补发旧记录；流身份变化时从持久起点返回换代后新事件，旧数值游标不会跳过恢复后较小ID的新事件。同流越界返回400，查询格式错误返回422，元数据损坏返回503，失败均不擅自换代。成功通知页响应带 `Cache-Control: no-store`；浏览器所有通知读取均指定 `cache: no-store`，不消费错误响应作为事件页；错误响应沿用统一处理器。原事件列表接口保持历史查询用途。

浏览器先校验和有界收集分页；分页中身份或起点改变则整批丢弃、稍后重试。每次轮询拥有独立可取消读取范围并绑定外部取消信号；本页或跨标签停用通知时中止在途请求，停止后续分页，旧请求收尾只释放自身范围。等候交付锁时被取消也不得发送通知或推进游标，立即重新启用不受旧请求收尾影响。跨标签页沿用Web Locks/IndexedDB同步交付锁，取得锁后重新读取共享游标：仅共享状态仍属于请求流或响应流时允许推进，已观察到第三个流则拒绝迟到响应；不同流身份不按数字或字典序比较。换代先保存新起点，通知构造失败仅推进已成功前缀；通知tag包含流身份。浏览器首次从旧版游标升级保留通知开关、建立当前基线并提示不补发旧记录；部署后需刷新所有旧标签页，不承诺混合版本协调。操作系统通知创建与持久化游标并非一个原子事务，成功不等于用户已看到，也不承诺进程崩溃后的严格一次交付。现行验收门槛与通知回归入口见[测试计划](TEST_PLAN.md)。

桌面通知在成功构造时捕获原流身份与事件字段，点击通过应用注入的导航回调打开笔记预警页。详情明确表示“通知触发时记录”，不按事件ID重新查询当前数据库；恢复、删除或后续数据变化不会把旧通知指向新事件。当前行情通过原工作台流程独立读取，导航序号、股票、加载序列和当前视图共同约束回写；行情失败遵循既有旧分析回退并明确区分通知股票。普通股票/主区/子页导航取消详情。摘要仅打开通用入口并显示原批量数量，不选择虚构的股票或记录。点击不改变通知游标、开关或自选未读；导航回调失败不把已构造的通知重新计作交付失败。

具体入口与签名见 [API 参考](API_REFERENCE.md)和[函数索引](FUNCTION_INVENTORY.md)；操作边界见[运行手册](OPERATIONS.md)。


### 2026-09-15：因子历史同口径与证据充分度

量价热度的当前计算及 `fund_flow_proxy` 历史 evaluator 共用 `price_volume_scoring` 的 `current-price-volume.v2`，不再使用K实体累计代理。历史只用当日与之前五个固定会话，要求PIT、日期连续、正量和可比较价格证据；停牌/公司行动窗口拒绝，未来后缀不能改变当时评分。`StandardFactor.score_rule_version` 与参与聚合的 `FactorCalibration.score_rule_version` 必须相同；双方缺版本的旧记录可读，单边新版本不能绑定另一边未知规则。

因子历史标签仍为信号后下一交易日开盘到固定D+5/D+10收盘，区别于概率模型H5的D+6退出。完整信号日至D+10窗口检查PIT、会话与价格；入场后公司行动的因子应用及锚无法证明时拒绝整个样本/分桶，不猜测除权损益。合法中间停牌保留会话计数，其携带OHLC不算有效触及；全部相似样本均因基准无效时明确执行证据不足。

`factor-evidence-sufficiency.v2` 取数据质量、历史校准覆盖、样本支持度三者最小值。每个独立正权重因子保留一份固定预算，样本支持为 `min(相似样本数/30,1)`，缺失为0再按全部固定份额平均；删除短板不能提升充分度。方向、盈利、胜率与信号强度不加分。30是工程饱和阈值，支持度不是统计置信度或预测概率。最低单因子样本数继续作为保守计数展示，不用于删除缺失因子后重分配支持。响应保留规则版本、分解与解释；旧报告没有新版本标记。历史场景固定顺序并列展示，未确认当前归属，不按收益择优引用。

个人方向离线验证v2新增独立 `prediction_diagnostics`：同日双类别AUC按日期等权，与pooled AUC分开；多个冻结基准精确绑定相同样本，比较日期等权Brier/log loss及成对改善；完整计划日期缺日或不足两个跨度块时不生成移动块区间。0.6/0.7阈值子集只作选择后的描述比较，不保证条件校准。该报告不修改训练配方、在线模型、正式概率契约或晋级权限。详细研究与下一阶段方案见[预测改进方案](PREDICTION_IMPROVEMENT_PLAN.md)。

### 2026-09-15：因子聚合v3

个股因子综合分按趋势与价位、量价、估值三组各1/3固定预算，组内份额不因缺失或画像转移；风险分低于50时仅扣分。新报告携带score_aggregation及逐因子score_share_pct/score_usage，旧报告默认为空。量能确认v2改为连续对称，且收盘同价/昨收绑定及连续20交易日校验通过才参与。当前实时趋势不能同口径历史重建，保留实时值但停止历史校准/百分位。Alpha准入复核参与标记及历史版本，多周期与诊断不重复叠加已有因子/市场证据。 公式、反例及限制见[评分第三版](SCORING_V3.md)。
