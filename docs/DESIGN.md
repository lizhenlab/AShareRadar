# Software Design Description

## 1. System Overview

AShareRadar is a local FastAPI + SQLite + static frontend application. The backend owns data acquisition, adjustment-aware caching, analysis, diagnostics, local user records, and runtime-data maintenance. The frontend is a server-rendered static page with modular JavaScript.

```mermaid
flowchart TD
  U["User Browser"] --> UI["static/index.html + static/app.js"]
  UI --> API["FastAPI routes"]
  API --> DI["AppContainer / deps"]
  DI --> WF["workflows.individual"]
  DI --> RC["RuntimeCoordinator"]
  DI --> MS["MarketScanManager"]
  RC --> SCH["LocalDataScheduler"]
  RC --> MS
  WF --> DH["DataHub"]
  WF --> SV["Analysis / Research / Insights / Alerts"]
  DH --> PR["Provider Registry"]
  DH --> EXT["External Providers"]
  DH --> CACHE["SQLiteCache + Repositories"]
  MS --> DH
  MS --> CACHE
  SV --> CACHE
  CACHE --> DB["data/ashare_radar.sqlite3"]
```

## 2. Runtime Composition

- `app/main.py` creates the FastAPI application, mounts revalidating static files, registers routers, and starts/stops the runtime coordinator.
- `app/api/container.py` builds the application container once: settings, datahub, scheduler, market scanner, runtime leadership/coordinator, and the DataHub-owned workbench context cache.
- SQLite composition is split by layer. `RepositoryBundle` creates repositories that share one path and process lock without performing domain reads; `DomainServiceBundle` is assembled and bound by `AppContainer`. API dependency functions resolve domain services from that bundle, and the scheduler receives the same `StrategyAutomationService` instance explicitly; neither production boundary locates a service through `datahub.cache`. `SQLiteCache` remains a compatibility façade for older callers, with lazy service composition only for cache-only use. Default paper-account creation belongs to idempotent schema bootstrap rather than cache construction.
- Full-market commands remain behind `MarketScanManager`, while `MarketScanQueryService` owns side-effect-free run/result/research reads, `MarketScanResearchStores` owns explicit artifact paths, and `MarketScanTerminalRecovery` owns the explicit terminal-recovery command. Ordinary GET/read calls do not repair or otherwise write lifecycle state.
- The same container owns one `MarketScanManager`. Its tasks are process-local, while the unique active-run database index is the cross-request/cross-process duplicate guard. The scheduler and manual API share that manager.
- `app/api/deps.py` exposes dependency functions to routes.
- `app/services/runtime_coordinator.py` owns one non-blocking advisory lock at `<SQLite path>.runtime-leader.lock`. Leadership activates the scheduler and full-market scanner together; a process that cannot acquire it stays available for reads, reports live standby state through service guards, and polls for takeover. Shutdown has a bounded synchronous phase, then keeps leadership through any non-cooperative scheduler/scanner task until both services report true quiescence. Only then can a standby take over both. Partial activation uses a restartable scanner rollback, so a transient scheduler failure does not permanently close the standby's scanner. The old `.scheduler.lock` and `.market-scan.lock` paths remain restore-time compatibility guards only; they are not independent runtime leaders. One Uvicorn worker remains the supported topology because task status and controls are process-local.
- Supported Uvicorn starts set `--timeout-graceful-shutdown 5`, bounding graceful drain of SSE and active HTTP data requests. This server deadline is separate from application cleanup and the daemon provider-worker exit guarantee; it cannot terminate a running SDK thread.
- `app/api/security.py` provides a same-origin mutation boundary ahead of route side effects. For `POST`/`PUT`/`PATCH`/`DELETE` and `GET` requests with a truthy `refresh` query, any request carrying browser origin metadata must have its Host-derived request origin in the configured allowlist, and any supplied `Origin` or `Referer` must independently resolve to an allowed origin; when those source headers are absent, explicit cross-site fetch metadata is rejected. This prevents an attacker-controlled Host/DNS-rebinding target from becoming trusted merely because its matching Origin is echoed. Default ports are normalized, ordinary read-only requests are unaffected, and non-browser clients without browser origin metadata remain supported.
- `app/api/errors.py` separates client request validation from internal model failure. `RequestValidationError` remains a Chinese `422`; a Pydantic `ValidationError` raised while mapping internal/provider/SQLite data is logged with traceback and returned as a generic `503` without exposing model input. Async routes use `run_sync_api_async()` for synchronous repository/diagnostic calls so SQLite work runs outside the event-loop thread while preserving the same not-found/domain/database error contract.
- `static/js/symbols.js` mirrors the public stock-symbol rule used by the backend for UI search input: normalize legal SH/SZ symbols, but reject malformed or all-zero codes before starting a workbench request.

### 2.1 Runtime Contract

The supported interpreter contract is executable rather than prose-only:

- Python must be 3.12.x. `.python-version`, Ruff, mypy, both hashed Python locks, and GitHub Actions use that baseline.
- Node.js 22.x is the default declared by `.node-version`; Node.js 22.x and 24.x are supported for development checks. npm 10.x and 11.x are accepted.
- `package.json` records `^22.0.0 || ^24.0.0` and `>=10 <12`; `tools/runtime_contract.py` verifies the installed versions and detects declaration drift across these files.
- The primary macOS quality job uses Python 3.12 and Node 22. A separate macOS Node 24 job runs the runtime contract and JavaScript smoke checks. Browser regression runs desktop Chromium, Firefox, and WebKit plus mobile Chromium on Ubuntu and does not redefine the supported local runtime.

Node is an engineering dependency for JavaScript checks, Playwright, npm auditing, and npm SBOM generation. It is not required by the FastAPI process at runtime.

### 2.2 Time Semantics

Time is separated by meaning and all direct wall-clock access is isolated in `app/utils/clock.py`:

| Meaning | Representation | Owner | Examples |
| --- | --- | --- | --- |
| Market/event time | aware `Asia/Shanghai`; legacy/UI market text may be Shanghai-naive | `market_now()`, `market_now_naive()`, `app/utils/market_time.py` | trading sessions, quote event time, K-line business dates, 15:15 publication boundary |
| Audit/persistence time | aware UTC serialized as ISO 8601 with `Z` | `utc_now()`, `app/utils/audit_time.py` | created/updated/fetched timestamps, task and scan lifecycle, provider status, health reports |
| Elapsed time | process-local monotonic/performance seconds | `monotonic_now()`, `performance_now()` | TTLs, deadlines, retries, throttles, latency and duration measurements |

`20260724_audit_timestamps_utc_v2` is an idempotent SQLite compatibility migration. For allowlisted audit columns only, it interprets historical `YYYY-MM-DD HH:MM:SS[.fraction]` values as Shanghai local time and rewrites them to UTC `...Z`, preserving fractions. Existing aware ISO values are left intact. Market-event columns are not bulk-converted, and `ashare_audit_epoch()` keeps mixed legacy/aware audit rows chronologically comparable during transition. Tests run with non-Shanghai host time zones to ensure business behavior does not depend on the machine setting.

## 3. Layer Responsibilities

| Layer | Files | Responsibilities |
| --- | --- | --- |
| UI | `static/index.html`, `static/app.js`, `static/js/*`, `static/styles.css`, `static/css/*` | Render workbench, call APIs, maintain local UI state, draw chart, handle SSE, and style UI surfaces by module. |
| API | `app/api/routes/*` | Validate request parameters, call workflows/services, select response models, and keep streaming event formatting isolated from provider logic. |
| Workflow | `app/workflows/individual.py`, `app/workflows/stock_analysis.py`, `app/workflows/workbench_pipeline.py`, `app/workflows/market_overview.py`, `app/workflows/stock_lookup.py` | Compose data into user-facing stock use cases while keeping public compatibility imports stable. |
| Services | `app/services/*` | Provider orchestration, analysis, indicators, quality gates, alerts, diagnostics, research reports. |
| Repositories | `app/repositories/*` | SQLite read/write boundaries per data domain. |
| DB | `app/db/*` | Connection, schema, migrations, row-to-model mapping. |
| Models | `app/models/*.py` | Pydantic API and internal transfer models grouped by domain, with `schemas.py` kept as a compatibility re-export layer. |

The checked dependency direction is `API -> workflows -> services -> repositories/DB`, with domain models and utilities shared downward. `db`, `repositories`, `models`, and `utils` may not import `app.api`, `app.services`, or `app.workflows`; production code imports domain model modules directly rather than the `app.models.schemas` compatibility facade. Provider error contracts and advice/rule constants therefore live in lower-layer model/utility modules, while service modules may provide compatibility re-exports. `tests/test_architecture_boundaries.py` also rejects application import cycles and direct `datetime.now()` outside the clock adapter.

Artifact byte handling is a separate lower-level boundary under `app/artifacts/io.py`. It supplies canonical finite JSON, bounded regular-file reads, `O_NOFOLLOW`/identity checks, deterministic gzip, and exclusive atomic content-addressed publication. Probability, probability-source, and future-range domain modules retain their own schema and semantic replay validators while delegating only these byte-level primitives. Golden byte/digest tests prevent a refactor from silently changing existing artifact identities.

## 4. Main Request Flows

### 4.1 Workbench Load

```mermaid
sequenceDiagram
  participant UI as Browser
  participant API as /api/stock/workbench
  participant WF as stock_workbench facade
  participant Cache as DataHub-scoped WorkbenchContextCache
  participant Pipe as workbench_pipeline
  participant DH as DataHub
  participant S as Services
  UI->>API: GET symbol
  API->>WF: stock_workbench(datahub, symbol)
  WF->>Cache: get(symbol)
  Cache->>Pipe: build_workbench_context if cache miss
  Pipe->>DH: quote/kline/profile/peers/concepts/order book
  Pipe->>S: analysis, insights, research reports
  S->>DH: provider/cache access as needed
  WF->>S: marks, alerts, notes
  WF-->>API: StockWorkbench
  API-->>UI: JSON
```

`stock_workbench` remains the public workflow facade, with provider-backed context construction, local state reads, and final response assembly separated. Interactive workbench and `/api/analyze` reads never persist a formal advice snapshot. The after-close active-research queue is the only publication owner: it starts at 15:15 or later and accepts only an official quote event in `[14:55:00,15:00:00]`, at least 60 valid completed bars, and passing date, quality, fallback and contract gates. Synchronous SQLite work in async workflows uses `run_cache_io()`/`run_cache_io_best_effort()` (`asyncio.to_thread`), and route-level repository calls use `run_sync_api_async()`, keeping database waits off the event loop. This includes market-sampling event logs, stock-lookup quote-confirmation/profile persistence, and quote-stream watchlist fallback reads rather than only primary workbench cache access. Local state helpers normalize the symbol themselves and use fixed read limits for chart marks, alert rules, alert events, and notes so user-state refresh behavior stays predictable even when the provider-heavy workbench context is cached. Local user-state read failures are logged best-effort and degrade to empty chart marks, alerts, events, or notes; optional enrichment such as market breadth, peer samples, order book, and concept membership has its own short workflow timeout and becomes missing-data context on expiry. These optional paths must not block the provider-backed stock analysis response.

The response contract is `stock-workbench-v2`. It declares
`research_mode=interactive_shadow`, `production_effect=none`,
`diagnosis_production_effect=none`, and a `WorkbenchResearchCohort` whose
`advice_persistence` is `disabled`. Context assembly validates the requested
canonical A-share symbol against the quote and every research child before cache
publication. The Pydantic response repeats that check across all research panels,
every strategy card, chart marks, alerts, events and notes; every research child
also supplies an `updated_at` no later than the context decision and on the same
Shanghai signal date. Quote timestamp, signal date and completed daily-bar cutoff
are bound to the same cohort. Independent child routes validate the same owner/time
contract, so direct reads cannot bypass the aggregate workbench. The browser
performs the same ownership/time validation before assigning state. A mismatch raises
`WorkbenchContextIntegrityError`, maps to the common non-disclosing research
integrity `409`, and cannot populate either the cache or DOM. The context cache
retains symbol single-flight but its freshness key also includes market-session
phase, expected quote date and expected completed-daily-bar date, so its 8-second
TTL cannot bridge a cohort boundary. Interactive concept membership is a stricter
cache-only optional path: it reads only fresh non-static provider-cache rows and
never starts an online concept-board scan. Cache miss, staleness, static-only data,
or read failure becomes unavailable context and contributes nothing to theme or
leadership scores. These rows carry no receipt/digest and cannot authorize a scan,
probability, filter, action, or publication.

Workbench analysis chooses `preopen`, `intraday`, or `official` semantics from
the trusted Shanghai session. Non-official modes exclude daily rows later than
the latest expected completed session, and live partial-session volume is neutral
rather than confirming a completed-daily signal. Optional market breadth keeps
only non-fallback quotes from the signal date; order-book rows must match symbol
and quote date; concept rows must additionally be non-fallback. Misbound optional
evidence becomes a sanitized warning/unavailable input instead of influencing
the environment, pressure or theme scores. Typed unavailable volume,
structure/chip, valuation, order-pressure, fund-flow, risk and calibration
evidence cannot participate in directional/current aggregates or leave stale
numeric/directional content after a DOM redraw. Missing target/stop inputs keep
reward/risk unavailable, and factor calibration requires a continuous unique
exchange-session PIT/execution/corporate-action contract. The diagnosis panel is
labelled as a non-persisted research diagnosis, not a second formal advice authority.

The three sensitive individual reads `/api/analyze`, `/api/stock/workbench`, and
`/api/stock/upside-probability` share an exception boundary outside dependency
resolution. Success, 4xx/5xx, request/response validation and unexpected
dependency/transport failures all carry `Cache-Control: no-store`; safe 4xx
details remain available, while 5xx and unexpected details collapse to one
generic individual-research unavailable message.

The workbench payload carries up to 240 daily K-lines. The current research path requires the explicit `qfq` contract; every provider series declares adjustment mode, as-of date, data version, contract version, and source before it can be cached or analyzed. The browser renders 20, 60, 120, or 240 rows from that payload without another HTTP request. Recommendation timeline, advice-review, and minute-analysis/chart data are companion requests with independent ownership guards, so one companion cannot repaint another stock. A valid timeline request immediately replaces prior content with a symbol-specific loading state; its symbol and stock-load sequence retain ownership through A-B-A switches. Minute responses are validated before state assignment, so empty/no-content payloads and symbol/interval mismatches clear the minute canvas and enter explicit unavailable state. A new minute interval issues one request; reselecting the active interval does not.

The main-query and watchlist inputs share a browser-side stock-search controller. A complete valid 6-digit code bypasses search and continues through the direct submit/add path. Other non-empty user input starts a 250 ms debounce, then calls the existing `GET /api/stocks` endpoint with an 8-item limit. The controller aborts superseded requests, rejects responses that no longer own the current sequence, caches at most 40 normalized queries with LRU eviction, and exposes separate loading, ready, empty, unavailable, and closed states. `stock-search-surface.js` owns Arrow keys, Enter, Escape, pointer selection, blur timers, persisted history selection, and page-hide cleanup through explicit state/DOM/fetch dependencies; `static/app.js` remains the composition entry. Autocomplete requests are outside the four-request stock-switch baseline and occur only after user input.

Daily and minute canvases expose immutable inspection snapshots from the rows and moving averages already used for drawing. `static/js/chart-inspector.js` maps CSS pointer coordinates to canvas plot coordinates and the nearest row; desktop pointer movement, touch/pointer press, and `ArrowLeft`/`ArrowRight`/`Home`/`End`/`Escape` share the same index model. The overlay reports event time, OHLC, open-to-close percentage, volume, enabled MA values, source, cache/fallback state, and fetch time. Redraws replace the snapshot and clear prior inspection state; inspection itself performs no HTTP request.

The tools view's local research activity is also a frontend projection rather than a new backend aggregate. `static/js/research-activity.js` validates, normalizes, and time-sorts existing recommendation timeline rows, alert events, and notes. The unfiltered view is capped at the latest 12 rows and each source filter at 20. Source ownership and loading/unavailable state remain independent, so one failed source can coexist with valid rows from the other two, while a genuine all-source empty result stays distinct. Existing note and alert mutation reload chains update their source arrays and then rerender the projection. This surface does not represent official announcements, news, or a company-event calendar.

#### 4.1.1 Individual D+2/D+3/D+4 Probability Research

The individual probability surface is a separate companion read, not another
field inferred during `StockWorkbench` assembly.
`GET /api/stock/upside-probability?symbol=...` returns the strict
`IndividualUpsideProbabilityReport` contract and does not delay the core quote,
K-line, analysis, or local-state response. The report contains one ordered row for
each `(display_day, holding_sessions)` pair `(2,1)`, `(3,2)`, and `(4,3)` plus
the frozen target contract, evidence counts/digests, limitations, and
`production_effect=none`.

All three labels observe a completed signal session D, use the fixed D+1 official
daily-K `open` as a no-shift price proxy, and test whether the daily-bar proxy net
return after declared round-trip costs is positive at the fixed D+2, D+3, or D+4
`close`. They are separate one-, two-, and three-session models; neither the
stock trend score, rule diagnosis, scenario weights, another horizon, nor the
full-market 1/5/20-session model can supply a probability. A fixed target that is
immature, zero-volume, missing, or version-conflicting remains unavailable rather
than moving to a convenient later session. The D+1 open proxy does not prove or
guarantee an executable fill. Locked-limit queues, order-book priority, market
impact and actual exit tradeability are declared limitations and remain outside
the V1 daily-OHLC label.

The typed model admits only `not_generated`, `insufficient_data`, and
`calibrated_shadow`. A horizon may carry `probability` and a confidence interval
only when the report and horizon are both `calibrated_shadow`, report-level
`evidence.selection_qualified` is true, and the child carries the point estimate
plus interval. Artifact evidence verifies each horizon's selection gates before
mapping its public status; `IndividualUpsideHorizon` intentionally has no
separate `selection_qualified` field. Every other state requires both numeric
fields to be null. The interval must be finite, ordered, lie in `[0,1]`, and
contain its point estimate. Model, feature, label, cost, training-cutoff, fold,
sample, metric and evidence identities remain explicit. Integrity digests prove
deterministic content identity, not authorship or predictive validity.

`individual_probability_artifact.py` is the offline evidence boundary. Current
builder schema
`individual-upside-probability-assessment-v4-source-intake-bound` persists the
exact estimator contract for the reused core schema/model, calibrators, baseline,
cost-model identity, empirical-Bayes hyperparameters, feature v3, label v3 and
split v3 constants. It binds each horizon's entry offset 1, target/purge gap
`H+1=2/3/4`, fit floor and two-fold selection floor. V4 admits an official date
only after loading all current source-artifact-v3 / snapshot-v3 records carrying
estimator feature-v3 and PIT-evidence-v4 from shared-action-gate-eligible snapshots.
The current intake must bind a writable `full-market-score-v5` contract and its
canonical publication replay receipt; source v2 and score v4 remain exact
historical audit inputs only.
It rechecks `quote event <= quote_observed_at <= run.as_of (decision)`, every
bar's date/aware `as_of` boundary and nondecreasing observation order. Its compact source identity includes
the source/run versions and digests, `as_of`/`captured_at`, run and registered
production score rule/spec, exact total/success/record counts, overall coverage,
and the full-market envelope. Compact verification rechecks that exact identity;
extra, missing or changed semantics fail closed. Assessment v1 and the former v3
shape are superseded and rejected. Assessment v2 remains loadable only under its
exact legacy shape for historical audit; its run/date/digest-only bindings do not
count toward the current report. The CLI
`tools/evaluate_individual_probability.py` accepts one deeply verified historical
manifest plus explicitly named official PIT source snapshots. It requires the
manifest-bound database to be a sidecar-free, non-link regular file within the
512 MiB registered size cap, rejects adjacent `<db>-wal`, `<db>-shm`, and
`<db>-journal`, and verifies identity, size, SHA-256 and content stability
across the complete read, then deserializes those exact verified bytes into an
in-memory SQLite database. One `query_only` transaction builds each holding
horizon independently without reopening the source path, closing the path-swap
window. Before publication it repeats the sidecar, identity, size, SHA-256 and
complete-byte verification; a source replacement or modification during the
evaluation therefore fails closed. The evaluator itself has no source-SQLite
write path. The retained
replay uses the frozen 11-feature OHLCV family and date-grouped Logit/calibration
engine; its fixed current-universe sample, unavailable historical
listing/ST/delisting state, provider/qfq vintage, missing amount/turnover and
daily-bar fill model remain declared limitations. Counting official sources does
not make that replay official. The compact, content-addressed JSON contains
source identities, aggregate OOS diagnostics and gate reasons, but deliberately
contains neither a current-stock point estimate nor reusable predictor
coefficients.

V4 source intake requires an aware, non-future assessment time and an aware
market-time sequence `quote_timestamp <= run.as_of <= captured_at <=
assessment.generated_at`. Quote and bar evidence remain bound to the trusted
official `data_date`. For current source v3, that date must exactly equal the
latest completed official session resolved from `run.as_of`; this accepts a
weekend/holiday capture of Friday's completed session without equating calendar
dates. It rejects pre-15:15 decisions, a prior session after the next session
matures, future/reversed time and unavailable calendar coverage. Source v1/v2
and previous-v2 assessment identities retain their frozen same-date rule. Every source row is
replayed against its PIT context and every successful scan row's registered
current `full-market-score-v5` specification and score details are deterministically
checked against persisted raw/trend/input/component values. The envelope contains
exactly ALL/SH/SZ/BJ; ALL must reconstruct from SH/SZ/BJ, the population floors
are respectively 4,000/1,800/2,500/200, and every scope requires 90% eligible and
95% success coverage. The individual intake additionally requires complete
records and at least 98% success-to-total coverage. A run ID cannot identify two
dates, and source/score contracts cannot drift across dates. Historical v4 rows
remain replayable but cannot contribute current official sessions.

The compact file still does not persist a source locator or the records needed
for a later runtime replay. V4 therefore proves that a normally built and loaded
source passed the stronger intake contract and that the identity survived the
compact verifier, but its outer SHA-256 remains a content seal rather than an
independent source-authenticity proof. The public projection keeps runtime source
replay false, projects official count 0 and signal date null, forces every child
to `insufficient_data` with null percentage/interval, and adds
`official_pit_source_artifacts_not_runtime_replayed` for a non-empty current
declaration. Locator-bound source replay remains required before calling a future
corpus independently attested. The tracked v2 baseline still retains
run 71 / `150cc48d…` and run 77 / `c085b6fa…` identities for audit, but those
source-v1 snapshots lack the new version/evidence binding and therefore contribute
zero current official sessions. Historical qfq OHLC values are adjustment-
normalized research inputs, not the cash prices an account could have traded on
those dates. Likewise the 10万元 notional rounded down to a 100-share lot is a
deterministic label-sizing proxy, not proof of historical buying power, order
placement, fill, capacity, or cash P&L.

`IndividualProbabilityStore` fingerprints and verifies immutable assessments.
Runtime-local files under `data/research/individual_probability/` take
precedence. When that directory has no candidate, the application reads the
tracked verified compact baseline under `docs/research/artifacts/`; any matching
but invalid runtime-local candidate fails closed instead of reviving the baseline
or an older artifact. Directory snapshots bind file name, device/inode/mode,
size, mtime, ctime and content SHA-256, must remain stable across verification,
and return deep copies so caller mutation cannot poison the cache. Two different
artifacts with the same latest `generated_at` are rejected as ambiguous. A
genuinely missing compatible assessment degrades to a typed null report.
Projection binds the current symbol and sets `signal_date` only from current-v4
official source dates after runtime source replay. Since replay is currently
unimplemented, the public `signal_date` is always null and official count is 0;
it never falls back to the non-official replay end date. It does not refresh
market data or unlock a percentage from historical diagnostics.
Even if that diagnostic later passes
a fit metric, official PIT readiness, official replay identity, selection
qualification and a persisted replayable current-stock predictor would all still
be required. Compact horizon metrics are not independently replayable, and no
current assessment reconstructs a point from the historical base rate. Without
that predictor the report remains `insufficient_data` with
`current_stock_replayable_predictor_not_persisted`, even if its other diagnostics
later pass. A public calibrated report requires 288 official and official-replay
sessions plus exact report-level digests. H1/H2/H3 require respectively
284/286/288 independent dates for two complete folds, at least 60 OOS sessions
per fold, at least two calibration bins and 20 sessions in the sparsest bin,
positive Brier skill in every fold, exact `1 - brier/reference_brier`, monotonic
bins/highest-bin lift, exact model/feature versions, a trusted exchange signal
date and an earlier trusted training cutoff. The longest D+4 split is 120 train,
4-gap, 40 calibration, 4-gap, and two 60-session tests, for a public required
count of 288.

`individual-probability-controller.js` owns an abortable request scope and the
active stock/load-sequence predicate. A new symbol cancels the prior companion
read; a late A response cannot repaint B or a newer A session. The contracts
module rejects symbol, schema, horizon, interval, state or target mismatches
before rendering. It also binds the report to the validated workbench cohort:
evidence dated after the workbench signal day is rejected, and a
`calibrated_shadow` report must match that signal day exactly; a null official
signal date remains the honest 0-session state. The view always creates three
D+2/D+3/D+4 cards, uses `—`
instead of a fabricated 0%/50%, and renders unavailable evidence independently
from the still-usable stock analysis. It never writes a score, advice, filter,
rank, strategy or order.

As of this worktree the tracked projection contains zero declared current-contract
signal dates versus the registered 288-session longest-horizon/two-fold floor;
there is not yet an independently replayable current PIT corpus. The two legacy
source-v1 identities in the tracked v2 artifact remain
auditable but are intentionally not upgraded. The separately attested history is
`official=false`, remains isolated from the current projection, and did not pass
its actual selection gates. Therefore the current report is `insufficient_data`,
`signal_date=null`, and all three probabilities/intervals remain null. It exposes
`legacy_official_pit_sources_audit_only_not_current_evidence` and
`compact_horizon_metrics_not_independently_replayable`. The retained 8,733-byte
assessment has integrity digest
`517691b101dcb2142693a74f6e5ac9ef10f386c545572b6bacfe161f186ba677`.

plan](research/INDIVIDUAL_SHORT_HORIZON_PROBABILITY_2026.md) records the primary

### 4.2 Full-Market Scan And Ranking

```mermaid
sequenceDiagram
  participant UI as Browser
  participant API as /api/market-scans
  participant M as MarketScanManager
  participant DB as MarketScanRepository
  participant DH as DataHub
  UI->>API: POST create scan with mode
  API->>M: create_scan(as_of, manual, mode)
  M->>DB: insert queued run with mode/data_date/quote_date
  M-->>API: 202 run snapshot
  API-->>UI: accepted or deduplicated run
  M->>DB: start run and seed full universe
  M->>DB: begin v6 quote capture
  loop every bounded quote chunk
    M->>DH: required-provider batch quotes
    alt provider response observed
      M->>M: freeze chunk with quote_observed_at
    else provider chain unavailable
      M->>M: bounded capture retry within wait budget
    end
    UI->>API: GET capture progress
  end
  M->>DB: seal exact-count capture envelope
  loop bounded K-line batches
    M->>DH: qfq K-lines with bounded concurrency
    alt usable or stock-specific outcome
      M->>DB: save success/missing/skipped rows and counts
    else provider chain unavailable
      M->>M: bounded batch recovery within wait budget
    end
    UI->>API: GET run progress
  end
  M->>DB: assign stable ranks and finish run
  UI->>API: GET pageable terminal results
  UI->>API: GET filtered XLSX export
  API->>M: export_results(published run, filters)
  M->>DB: read complete filtered snapshot
```

`MarketScanRuntimeGuard` gives the whole executor a 30-minute monotonic deadline and rechecks the run's mode-specific `data_date` and `quote_date` before seeding, before each batch, and before completion. An intraday run stops rather than publishes if it crosses 15:15 or the current quote session changes. A `preopen` run likewise stops if the local date is no longer a trading day or the clock reaches the 09:15 call-auction boundary. Timeout or date drift stops the run without fabricating per-symbol missing rows. Finalization queries a publication summary over ALL/SH/SZ/BJ coverage, stale-date clusters, capture-envelope integrity, observation timestamps, per-market quote event times, and versioned score-distribution diagnostics. Every scope must reach 95% success coverage over `success + missing`, at least 90% of each market must remain eligible after deterministic skips, and v6 must have a sealed exact-count envelope plus complete parseable `quote_observed_at` evidence. Capture duration, the global observed-time span, and each market's event-time span independently have a 20-minute ceiling. The event-time spread across SH/SZ/BJ is diagnostic only; systemic stale or collapsed-score distributions still block or degrade publication. Suspension, single-price, and short-history outcomes remain visible as `skipped`; the separate eligibility guard prevents systemic bad data from being hidden as mass skipping.

Publication is also a database-local integrity transition. `market-scan-snapshot-digest-v2` hashes strict finite canonical JSON containing every public persisted `market_scan_run` field except `snapshot_digest` itself and every public persisted `market_scan_result` field, including the public `metrics` and `score_details` projections, with results ordered by symbol. `market_scan_integrity.py` reconstructs the identical canonical object byte order incrementally: it writes the contract/results prefix, iterates the symbol-ordered SQLite cursor, strict-decodes and canonicalizes one row, writes exact separators and row bytes into SHA-256, then writes the canonical run and suffix. It does not call `fetchall()` for results or retain the full graph, so verifier memory is `O(max canonical result row)` rather than `O(result count)`. The byte contract—including empty results, Unicode escaping, float serialization and strict duplicate-key/non-finite rejection—remains v2; no new migration marker, stored-digest rewrite or reseal is permitted for this implementation change. Progress, coverage, elapsed, throughput and ETA are derived from those sealed inputs instead of being independent unbound claims. The same transaction checks `finished_at <= updated_at <= snapshot_sealed_at` and every result `updated_at <= run.updated_at`, stores `snapshot_seal_origin=publication`, and creates the digest before the caller may observe the terminal publication.

Five database triggers make the sealed graph append-closed: `trg_market_scan_published_run_immutable` and `trg_market_scan_published_run_no_delete` reject run update/delete, while `trg_market_scan_published_result_no_update`, `trg_market_scan_published_result_no_delete`, and `trg_market_scan_published_result_no_insert` reject every child mutation. `verify_market_scan_snapshot()` accepts either a valid original `publication` seal or a migration `legacy_backfill`; `require_publication_market_scan_snapshot()` accepts only the former. A legacy backfill attests migration-time graph consistency, not original publication-time authority. Run `#80` therefore remains digest-verifiable audit evidence but cannot authorize a new action.

The authorization split is deliberate. `app/db/market_scan_action_source.py` is the frozen shared lower-level action gate. It first verifies the original `publication` seal, then exact scope `沪市 + 深市 + 北交所当前上市A股`, then strictly parses `market-scan-publication-diagnostics-v1`. Authority exists only when `blockers` is empty, `passed_gates` contains exactly one `code=score_distribution.pass` with `severity=info`, neither blockers nor source warnings contain any `score_distribution.*` code, and no other score-distribution code appears as passed. A valid digest, origin, status, or display label by itself is insufficient. Consumers can require stronger official/date/header/result/rank/score/production-contract evidence but cannot weaken that shared gate.

History/detail/latest/results, publication-summary inspection, breadth/screen evaluation, offline evaluation and backup verification may audit a digest-valid action-ineligible snapshot and must expose its origin/diagnostics. Discovery queue/apply/leaderboard/rank actions, delta and screen-alert persistence, strategy execution/simulation/executable Shadow/evidence/automation, probability capture outbox/filter/use and managed publication, future-range research, TOP100 refresh, and degraded retry-copy require the shared gate; two-run consumers require it for both inputs. A v6 retry that preserves no source rows and performs a fresh full-universe recomputation follows the separate unsealed lifecycle contract. Failed/cancelled/interrupted retry lifecycle likewise remains distinct. This prevents a later internally consistent migration read or contradictory score-diagnostic payload from becoming retroactive action authority.

The API does not disclose which seal or artifact invariant failed. `artifact_integrity_guard()` maps a database snapshot-seal error to the generic market-snapshot HTTP `409` and maps probability, future-range, snapshot-model, strategy-evidence and automation integrity failures to the generic research-artifact HTTP `409`. This cache policy prevents reuse of sensitive research responses; it does not independently attest their integrity.

`Asia/Shanghai` 00:00 for comparison with that bar date and the run decision;
ordinary timestamps keep their existing absolute-time semantics. A future
date-only value, non-canonical spelling, decreasing observation order, or value
outside the bar-date/decision interval fails closed. The exception lives only
inside skip-PIT verification and does not weaken artifact, quote, run, or audit
timestamp validation.

Production run `#86` is the negative boundary for this rule. Its immutable
failed/unpublished graph records 5,389 success, 154 missing and 0 skipped because
canonical provider date-only K-line snapshots did not pass the former skip-PIT
parity path. Read-only replay of that frozen input finds 146 typed exclusions:
38 `new_listing_insufficient_history` and 108 `official_session_gap`, covering
7,673 bound bars. A new run under the corrected verifier is expected to conserve
5,389 success + 8 missing + 146 skipped = 5,543. This counterfactual replay is
not a migration, publication, repair, or reseal of `#86`.

Publication reads all success rows through compact projections rather than hydrating result models. Policy `score-layer-distribution-v4` requires complete base, integer, final and component evidence; it audits sample/distinct counts, Shannon entropy bits, normalized entropy, effective distinct count, effective precision digits and population variance, plus full leader, trend, data-quality and rank-refinement coverage/variance. It also verifies the exact leader/trend alias relation. A raw-only projection fails, a zero-variance component is reported, a constant base fails, and a low-entropy/tied base apparently diversified only by six-decimal refinement degrades. `market_scan_success_score_contract(run_id)` separately returns the inner production score rule/hash only when every success row is covered and the pair is unique; missing or mixed contracts fail closed to `None` for probability binding.

`GET /api/market-scans/polling-identity` is deliberately not a cheaper trust path. In one query-only SQLite snapshot it reads only the global-latest and mode-scoped latest-published run headers, binds both tokens and the combined fingerprint to the database path/device/inode/schema identity with separate SHA-256 domains, and returns only `{run_id, token}` slots. It performs no result-table read, snapshot verification, receipt replay, or action admission. The `run_id` is diagnostic/change-detection data and never selects the displayed run. On initial load, force, or fingerprint change the browser sequentially calls the existing fully verified `latest` and `latest-published` selectors and uses only their trusted published ID for the result request; a stable identity-before/after pair is required before committing the new baseline. At most two attempts are made, concurrent ticks coalesce, selector failure cannot leave a sibling full-hash request behind, and mode/history/surface/user-query changes invalidate the same request generation. History browsing defers current-result replacement. Query page/probability state is retained only when the trusted published binding is unchanged; a changed trusted run resets page one and removes the old probability filter before its first read.

High-frequency active progress is excluded from the opaque token: queued/running/cancelling headers normalize `updated_at` out of the fingerprint, while run ID and status remain bound. The first discovered active run is confirmed through the trusted selectors, after which the existing two-second `/{run_id}` tracker owns progress; queued-to-running and terminal/seal transitions still change identity. An unchanged idle tick therefore issues one small identity request and zero full snapshot hashes. Result-only tamper intentionally does not change this header identity. It fails closed at the next results/probability/export/action trust boundary and at the scheduler's independent five-minute full audit; selected-header, seal, database-file, and schema changes are detected immediately. The polling identity is never persisted as a receipt, passed into the verified-read capability, or allowed to enable filtering/export/actions.

A stable failed fingerprint is also non-authorizing state. A deterministic frontend contract error, integrity/other HTTP rejection, or timeout after dispatch suppresses further full-selector reads on ordinary ticks until the opaque fingerprint changes or the user explicitly forces one attempt. Only the exact controlled admission-busy `503` follows transient `Retry-After` backoff; failed staging never commits the polling baseline or replaces trusted display state. Server-side, one container-owned `MarketScanHeavyReadAdmission` supplies a process-local capacity-one, nonblocking slot shared by `latest`, `latest-published`, run detail, and results. Busy requests dispatch no worker and receive an exact no-store `503`; accepted calls never share or cache results. The admission owns a strong task reference and releases its lease only in the actual worker's `finally`, so caller cancellation, garbage collection, and late exceptions cannot expose a false idle slot. Admission, worker creation, and tracking are atomic under one guard; closing rejects new work and drains the owned set before runtime, workbench, and DataHub resources close, even if the shutdown waiter itself is cancelled.

Run progress uses one coverage formula across Python and JavaScript: `success_count / (total_count - skipped_count)`, or zero when the eligible denominator is zero. The read mapper may normalize the frozen pre-`publication.canonical_replay.v1` legacy representation, including run `#85`, but the current write contract and every arbitrary count/percentage mismatch remain strict failures. This compatibility projection does not rewrite or reseal the source run.

The scheduler calls `scheduled_tick()` once per loop and creates `official` runs only. The manager accepts an automatic run only on a trading day after both the configured schedule and the 15:15 publication floor; it never creates or retries an intraday or `preopen` run. A successful/degraded/active run or manual cancellation for the same data date suppresses another automatic run; a failed scheduled/retry attempt is not recreated every second. The unique active-run guard prevents scheduled and manual work from overlapping. After one complete snapshot verification establishes a terminal same-day no-action decision, the manager caches only a cheap `MarketScanAutomaticState`: the persisted publication header, database file/schema identity, lifecycle-guard epoch and audit time. Matching one-second ticks may skip the whole-graph verifier for at most five minutes, and unrelated monitor-table writes do not alter that identity. A market-scan header/database identity or leadership-epoch change, or expiry of the five-minute interval, sends the decision back through full verification. The state is a duplicate-decision hint only: it cannot authorize a publication or downstream action, and normal repository/API snapshot reads continue to verify the full sealed graph immediately.

Full-market retention treats `ASHARE_RADAR_MAX_MARKET_SCAN_RUNS` as the newest-run keep window for unprotected graphs, not an unconditional physical-row ceiling. `market_scan_retention.py` removes every otherwise eligible unreferenced graph outside that window and protects active work, every dynamically discovered foreign key into `market_scan_run`, and the declared non-FK Discovery/strategy references. Retry reachability uses as roots every retry child that is not in the current delete-candidate set—including retained-rank, `queued`, `running`, `cancelling`, database-referenced and file-referenced rows—plus every directly protected candidate. It follows `retry_of_run_id` parents through both candidate and noncandidate nodes and pins every reachable candidate ancestor, preventing `ON DELETE SET NULL` from detaching a retained lineage. A visited set makes even a legacy cycle finite; the schema self-FK plus repository `foreign_keys=ON` prevents new missing parents, while an already missing parent simply terminates that branch. A run's own `task_run_id` is an outward ownership link and does not pin the run; scan cleanup precedes task cleanup so its now-unreferenced task may become eligible in the same pass.

`runtime_research_artifact_retention.py` adds the file side of that reachability graph. Its catalog is closed and stable: relative to the database sibling it strictly enumerates probability result, source, outcome, fit, future-range and individual-probability directories without following links, plus the fixed future-range summary. The tracked `docs/research/artifacts` individual assessment is enumerated only for the exact canonical project database and only when the strictly scanned runtime-local primary contains no files; a temporary or otherwise custom database never borrows project fallback evidence. It checks each directory artifact's applicable filename/content identity and integrity digest, recursively extracts explicit `*run_id`/`*run_ids` values, and pins exactly those runs. Fit `through_run_id` is not expanded into an invented numeric range; only explicit members pin. The summary separately requires `market-scan-future-range-evaluation-summary-v1`, exact `artifact_count`, valid per-item run/digest identity, and `offline_replay_verified=true`, then pins only those explicit runs. An unknown file, invalid shape/digest, unsafe object, changed directory/file fingerprint, or invalid summary fails the cleanup rather than guessing. Artifacts are not deleted by this path.

`runtime_probability_artifact_stream.py` handles probability files larger than 64 MiB without materializing the JSON tree. Its memory bound depends on fixed read/tail budgets rather than artifact size. It validates the canonical outer envelope, SHA-256 algorithm/notice and filename digest, both historical `scope=payload` and current `scope=generated_at+payload`, the filtered nested `generated_at` semantics used by the writer, singleton artifacts with no manifest, every scalar `run_id`, and sorted unique `artifact_set_run_ids`. An incomplete long manifest may span read boundaries up to its explicit stream budget; equal-length semantic tamper, unexpected generation-time encoding, a scalar outside the manifest, or file-size drift fails closed. Small artifacts continue through the ordinary deep verifier, so the two paths preserve the same run-reachability meaning.

`market_scan_artifact_lease.py`, `market_scan_artifact_paths.py`, and `market_scan_artifact_rollback.py` close the file/SQLite commit race. Cleanup enters the per-database lease before its first artifact scan and holds it through database commit. Managed writers enter the same lease before the final read-only shared action-source validation—original publication, exact full scope and consistent diagnostics-v1 score gate—and hold it through the last atomic link. The in-process layer is an `RLock`; the cross-process layer uses a per-database sidecar derived from one canonical lexical database path under fixed `/tmp/ashare-radar-artifact-locks-<uid>`. Database symlinks, hard links, parent-namespace replacement, sidecar replacement, and cross-database nested leases are rejected. The root is owner-only mode 0700, but the threat boundary trusts cooperating processes and the filesystem authority of the same UID; it does not claim resistance to a malicious same-UID process deliberately renaming the root.

The six managed families—probability result, source, outcome, fit, future range, and individual probability—bind the exact project-managed path to canonical `data/ashare_radar.sqlite3`. A lexical alias, linked parent, alternate database, or batch mixing managed and external targets is invalid. External destinations do not acquire managed-runtime semantics and remain offline/self-contained. Nested batches may only narrow the parent's database, target set, and run IDs. Every newly linked file is journaled as `(path, size, sha256)`; failure in the body or final namespace check walks the whole journal in reverse, stream-verifies exact regular single-link identities and unlinks them with directory fsync. Identical pre-existing immutable files are never journaled or rolled back. This gives a managed artifact set all-or-nothing publication without retaining artifact bytes in memory.

Deletion is a separate narrow database capability in `market_scan_integrity.py`. It requires the caller's explicit write transaction, installs and verifies the exact five immutability triggers, verifies every candidate's v2 sealed graph, temporarily removes the triggers, deletes all child results and the run, restores and re-verifies the triggers in `finally`, and requires an exact parent deletion count. The maintenance transaction rechecks the file-artifact snapshot immediately before graph deletion and again before commit. Any tamper, reference/catalog drift, injected SQL failure, incomplete graph deletion, or trigger-restoration failure rolls back the whole cleanup. This bounded deletion authority does not weaken ordinary sealed-graph immutability: a SHA-256 snapshot digest is neither a backup nor an archive and cannot reconstruct a graph after an authorized deletion.

### 4.5 Advice Reviews and Watchlist Scan

An advice-review plan is bound transactionally to one persisted advice snapshot, including symbol, market time, entry price, `qfq` anchor/data contract, and rule version. Creation enforces `target > snapshot > stop`, a 1-60 trading-day horizon, required hypothesis/trigger/invalidation text, and the explicit executable bases `daily_high_gte_target_price` / `daily_low_lte_stop_price`. Automatic snapshot evidence is always merged ahead of user text and carries stable ID, value, direction, data date, nature, and rule version; clients cannot replace system-owned structured evidence. The mutable plan row is only a current projection. Creation and each material edit append canonical finite JSON plus SHA-256 to `advice_review_plan_revision(plan_id, revision)`; active reads join that exact ledger row and reject a missing, non-canonical, digest-mismatched, or projection-mismatched revision. Repeating an A→B→A edit remains three independently auditable revisions. Update, evaluation, paper-strategy creation, and archive operations compare the expected revision under a write transaction. Archive sets `deleted_at` and removes the projection from active queries without deleting the advice snapshot, revision ledger, or results.

Evaluation has its own append-only attempt ledger. The exact plan revision digest, canonical evaluation input, canonical result, and entire source row window—including PIT/execution/suspension/corporate-action metadata—receive separate SHA-256 bindings. The current `advice-review-evidence.v2` input digest also binds the server audit time and attempt, so tampering either ordering field invalidates the row. An identical semantic input/result pair is idempotent; a different canonical input or result for the same `(plan, revision, as_of, rule)` receives the next attempt. Current detail and summary order by `as_of`, attempt, `evaluated_at`, then ID and consider only the current plan revision. Stored rows are never rewritten during a read: legacy v1/legacy-unverified, provenance-invalid, digest-mismatched, or plan-ledger-mismatched evidence is projected as metric-free `insufficient_data` and contributes no hit, return, MFE, MAE, or favorable count. Status/conclusion, hit/date, window/count, metric, and time cross-fields are strict model invariants. `as_of` cannot be in the future or precede the snapshot; it is rejected before plan or market-storage reads. `evaluated_at` is a server-owned trusted audit time and cannot be future-dated.

Forward evaluation cuts completed daily evidence at 15:15 Shanghai time and enumerates fixed sessions through the trusted exchange calendar. It requires unique, ordered, non-fallback PIT `qfq` rows with one supported data contract plus complete execution/suspension/corporate-action metadata. A missing fixed session, invalid date, conflicting duplicate, mixed contract, or unverifiable adjustment anchor closes the result. A suspended row is an expected session, but its carried OHLC cannot trigger a barrier; a suspended terminal session cannot become a horizon result. Target/stop ends the observation window at the first event, a same-day double touch is `target_stop_ambiguous`, and daily OHLC never claims the unavailable intraday order. Selecting today omits `as_of`; a past date maps to Shanghai-local end of day. The bounded due task selects oldest trusted-calendar due keys, rechecks the live revision, and isolates each plan failure.

The browser treats the workspace as local Research Shadow with `production_effect=none`. `advice-review-contracts.js` validates owner identities, revision/digests, time/window/count conservation, status/conclusion/metric cross-fields, and summary denominators before rendering. `paper-trading.js` separately validates run/output-digest identity, strategy and symbol membership, child run ownership, and strategy/execution/closed/unavailable count conservation before replacing state or DOM. Symbol/plan/sequence ownership suppresses A-B-A responses. Summary, due queue, and all-plan pages load with `Promise.allSettled`, so a failed projection is local rather than destructive to healthy sections. Every review or Paper response, including validation and failure paths, is `no-store`; unexpected 5xx content is replaced with the generic research-unavailable detail.

The after-close active-research task selects at most 100 non-excluded watchlist symbols, prioritizes missing/outdated snapshots, and rotates ties for fairness. It calls the deterministic single-stock workflow with history persistence disabled, then saves only when quote/K-line data dates, quality, `qfq` provenance, and rule/advice contracts are current. One-symbol failures are sanitized and do not abort the batch; unchanged current conclusions do not write a duplicate. Advice insertion and unread increment remain atomic. The browser clears unread through the advice ID it actually displayed, so a later background change remains unread.

`POST /api/watchlist/scan` accepts only the versioned fixed conditions `close_above_ma20`, `close_below_ma20`, `breakout_20d_high`, and `volume_surge_5d`. The Replay workspace lets the user select the active, non-excluded watchlist or enter a normalized, de-duplicated custom universe, and optionally choose a historical cutoff date. Both paths are capped at 50 symbols, use completed daily bars at the requested `as_of`, fetch through the ordinary `qfq` DataHub path with concurrency five, and return successful evaluations separately from sanitized missing-data rows. The browser renders the returned `as_of`, rule version, condition decisions, and metrics as read-only historical evidence; the row itself never opens the current workbench. A separate `查看当前分析` action explicitly leaves the historical context. Today follows the same server-current-time rule as review evaluation; only a past date sends an explicit Shanghai end-of-day cutoff. A row matches only when all selected conditions match; arbitrary expressions or scripts are not accepted.

Paper simulation freezes one exact current review-plan revision and digest. The service performs an early check for readable feedback, then the repository repeats the plan/revision/current-projection/ledger-payload/digest CAS inside `BEGIN IMMEDIATE` and inserts values from that database row. Strategy lists and simulation admission rebind the stored frozen fields to that immutable revision before use. At most one retained strategy row may reference a plan revision; a never-run row may be deleted and recreated, while a row referenced by an immutable run cannot be deleted or semantically overwritten by import. Account principal is editable only before the first strategy or run. Simulation accepts only the completed source window through its stable `as_of`, requires continuous canonical exchange sessions and complete PIT/execution evidence, rebases frozen prices against the verified `qfq` anchor, and fingerprints every price, provenance, execution, suspension and corporate-action field plus effective rule/cost/benchmark configuration. Listing-day price-limit selection uses `trading_session_count(listing_date, trade_date)` over an inclusive trusted range: a listing date equal to the calendar's left boundary is session 1 and is covered, while a date before that boundary produces `trading_calendar_out_of_coverage` and no assumed limit. Suspended/zero-volume or explicit unavailable sessions do not fill; an open position is not marked to a carried suspended close, and a pending exit remains latched with a blocked event until a sellable session. T+1 defers entry-day exits, benchmark/equity use trading sessions only, and every saved run/results/trades/equity/events set is append-only. `20260813_paper_trading_output_digest_v3` hashes the complete persisted run projection consumed by dashboard/export reads: run inputs and configuration; plan-revision/digest/symbol strategy identities; deterministic allocation/sequence/date ordering; and all strategy results, trades, equity and events. It deliberately excludes database surrogate IDs and audit timestamps, so pure ID remapping is stable, and every historical-run read recomputes the digest before returning data. Canonicalization retains every child before validating that a non-null strategy belongs to the same run and symbol; it also recomputes declared strategy/execution/closed/unavailable counts. An orphan cannot disappear through an inner join or acquire a newly valid digest. Dashboard/export performance reconstructs its denominator from the selected run's frozen `configuration.initial_cash`, never the current account projection. This remains a daily-bar model with no broker, order-book, queue-position, intraday-path, market-impact, or guaranteed-fill semantics.

The review result and paper run retain digest commitments, counts/source summaries, and derived evidence, not a content-addressed copy of every raw K-line row. They can validate a supplied source window against the commitment, but an ordinary export is not by itself a permanent standalone market-input replay package after cache retention or provider revision.

### 4.6 Local Data and Runtime Operations

User-data export/import is a versioned, strict JSON contract over an explicit table allowlist. Merge is source-wins only for mutable stable-key rows; replace requires all currently available user-data tables. Review plans must travel with their revision ledger. Preflight verifies canonical revision JSON/SHA-256, current projection/revision binding, result and paper references, plan/advice identity and paper-run output commitments; a partial paper bundle that cannot reconstruct a declared run commitment fails closed. Legacy bundles missing the later output column remain audit-readable only through explicit compatibility normalization and target-side rehash. Surrogate remapping rewrites foreign keys plus the canonical revision payload's embedded advice ID, recomputes its digest, and propagates that digest to plan/result/paper rows. A pure surrogate-ID remap preserves paper output v3; a complete graph whose embedded identity changes is rehashed after the semantic-preserving remap. By contrast, partial/source-wins import rejects an account update once any Paper strategy/run exists and rejects any semantic update to a strategy already referenced by `paper_strategy_result`; it rolls back rather than blessing changed history with a new digest. An older incoming plan cannot roll back a target revision, and a same-key different revision/result ledger row is an immutable conflict rather than an update. The same relationships and SQLite foreign keys are checked again after simulated writes. Dry run executes that transaction before rollback. Preview and commit run under `SQLiteCache.exclusive_local_data_operation()`; a ten-minute single-use claim binds path, mode, bundle, timezone, and current user state. Commit consumes it under the same lock, rejects drift, creates and verifies a full runtime rollback backup, then applies the import. Browser file/preview/commit/cleanup operations carry generation ownership and a 50 MB cap; only a successful current import reloads caches/panels and rebuilds quote SSE.

Full runtime backup is separate from user-data portability. `app/services/runtime_backup.py` creates a consistent SQLite snapshot and manifest, verifies its hash, schema/user versions, row counts, `PRAGMA integrity_check`, and an empty `PRAGMA foreign_key_check`, and restores through a staged atomic replacement followed by the same verification. Operations for the same database or backup directory acquire thread locks and cross-process file leases in sorted path order, with one 30-second deadline across acquisition. Creation, verification, rotation, restore-source staging, rollback creation, and pruning stay inside that lease, so concurrent callers cannot delete a bundle being verified/restored and managed retention still converges to `ASHARE_RADAR_MAX_RUNTIME_BACKUPS`. Restore also requires an explicit stopped-service acknowledgement, refuses the unified `runtime-leader` lock, either legacy `.scheduler.lock`/`.market-scan.lock`, or an active database, and creates a rollback snapshot of the current target. It additionally enters the market-scan artifact lease with missing-target support before inspecting or replacing the target. Because the backup bundle contains only SQLite, restore refuses a populated sibling probability/source/outcome/fit/future/individual managed directory, the fixed future summary, or—for the canonical project database with no runtime-local individual files—a populated tracked docs fallback. That conservative gate runs before replacement and treats unsafe/unreadable paths as failure; a database and its side artifacts must be restored as one separately audited set. API and CLI callers explicitly pass the configured limit so one operation cannot silently use a different process-global value. Automatic scheduler cleanup calls the regenerable-only retention path, so it cannot delete watchlists, rules, notes, review data, alert events, or advice history. User-invoked cleanup has a non-mutating preview; if alert/advice history is eligible, it creates a verified rollback backup before deletion. Advice snapshots referenced by active or archived review plans are never retention candidates.

Latency-sensitive dashboard statistics, provider status, and published market-scan reads use explicit SQLite query-only snapshots. They remain internally consistent without waiting for unrelated in-process repository writes. Logical retention still uses the shared write lock, but best-effort physical compaction releases that lock before `VACUUM`; SQLite's short busy timeout decides whether compaction can proceed without freezing dashboard reads.

Retention uses window-function candidate queries and one set-based `DELETE` per table instead of Python partition loops. Quote history is bounded per symbol, daily K-lines per symbol and adjustment, minute K-lines per symbol and interval, and concepts per symbol; scans, tasks, cache/monitor events, and explicit user-history limits are global. Automatic regenerable maintenance is monotonic-time throttled by `ASHARE_RADAR_RUNTIME_MAINTENANCE_INTERVAL_SECONDS` (one hour by default), so frequent health checks do not repeatedly scan SQLite.

`GET /api/system/diagnostics` combines cache fetch activity and market freshness with provider/capability state, scheduler state, storage budget, categorized row counts, warnings, and suggestions. Cache freshness includes stock-pool and plate metadata alongside quote and daily/minute K-line domains; existing metadata rows without a usable timestamp are diagnosed as missing rather than silently skipped. Storage reports total bytes plus separate SQLite and managed-backup bytes/count, and separates quote, K-line, full-market-scan, other cache, other runtime, and user row groups. Scheduler responses preserve `degraded` task outcomes for fallback/partial runs and expose standby ownership separately from a stopped scheduler.

Browser alert notifications remain a client-side opt-in with a persistent enabled/disabled preference. After a user permission action, enabling establishes a no-backfill event-ID cursor in local storage, then drains keyset-paginated alert events every 30 seconds, notifies only later `触发` rows, and collapses bursts above three events. Disabling stops and invalidates polling and clears the cursor; re-enabling creates a fresh baseline so the disabled interval is not replayed. Pagination failure leaves the persisted cursor unchanged; notification-construction failure advances it only through the successfully delivered prefix, so the failed event and all later events are retried in order. There is no closed-page background worker.

## 5. Data Model Summary

SQLite initialization enters through `app/db/schema.py`; table/index definitions live in `app/db/schema_definitions.py`, while guarded compatibility columns, one-time migrations, migration records, and compatibility indexes live in `app/db/schema_migrations.py`. Upgrade ordering is part of the trust contract. If the market-scan seal columns do not yet exist, startup first drops any prematurely created immutability triggers; it then creates the base and Discovery schema. All compatibility columns/backfills/indexes run inside one rollback-capable `BEGIN IMMEDIATE`, with the market-scan v2 snapshot migration last: every pre-existing published graph is reset to origin `legacy_backfill`, sealed, verified, guarded by five triggers, and marked only after success. Advice-review and Paper schemas follow. Strategy Lab runs last in its own transaction, verifies every surviving source run, adds/backfills execution source digest/origin/status, retains an orphan as null/null/`legacy_unverified`, validates the exact two-state relation, recreates append-only/source-insert guards, and writes its marker last. The marker-present path still revalidates safe state and restores missing guards. This ordering prevents triggers from referencing absent columns and prevents strategy history from claiming an authority its source migration did not establish. All startup schema changes are offline upgrades: verified backup, stopped old processes, one new-version writer, adequate disk space, then integrity/foreign-key validation before service admission.

Indexes that depend on compatibility-added columns are created only after those columns and row backfills exist, so partially upgraded databases can initialize idempotently. The advice-review v4 compatibility path disables foreign-key enforcement only when its legacy result-table rebuild requires it, performs the rebuild/backfill/index/migration-marker work under one `BEGIN IMMEDIATE`, runs `foreign_key_check`, rolls the whole upgrade back on failure, and restores the prior enforcement setting. Row-to-model mapping is split by domain so repository changes can stay close to the data they read. Pydantic models are grouped by API/domain so response contracts can evolve without one oversized schema file:

| Module | Purpose |
| --- | --- |

## 6. Provider Design

Provider construction and capability checks are centralized in `app/services/provider_registry.py`. The registry owns capability-filtered priority lookup, optional demo insertion, capability-kind field mapping, fallback capability metadata for providers without an explicit `capability()`, and the enabled checks used by `DataHub` status synchronization. Environment-backed priority tuples are normalized and de-duplicated by `Settings`; unknown environment names fail startup, while code-level custom providers remain extensible. Futu participates in quote fallback only when OpenD support is enabled and installed, and token-backed Tushare participates in daily-K fallback before BaoStock.

Default priority:

```text
Quote:  Tencent/Eastmoney -> Futu (when enabled) -> AKShare
Daily:  Tencent newfqkline (SH/SZ/BJ) -> AKShare [Eastmoney -> Sina qfq] -> Tushare (when configured) -> BaoStock
Minute: Futu -> AKShare
Stocks: AKShare -> Tushare -> BaoStock -> Local
Plates: AKShare -> Local
```

Provider calls must:

- Use bounded timeouts.
- Record success/failure per capability.
- Avoid marking a whole provider unhealthy when only one capability failed.
- Prefer explicit degraded/fallback context over fake real-time data.
- Reject malformed critical quote/K-line fields and empty order-book depth instead of silently converting them to usable data.
- Reject quotes with missing stock code/name, impossible timestamps, or open/current prices outside the reported high/low range.

Provider support modules:

- `app/services/providers.py` keeps one Tencent `httpx.AsyncClient` per provider instance so thousands of daily-K requests reuse HTTP keep-alive connections instead of constructing a client for every stock. Shutdown starts one shielded close task after `ProviderRuntime` is quiescent; caller cancellation cannot cancel the transport close, new requests fail closed once shutdown begins, and a failed close is never reported as success.
- `app/services/datahub.py` owns high-level DataHub orchestration, the runtime settings instance, SQLite cache wiring, provider coordinator construction, and the DataHub-scoped workbench context cache. - `app/services/datahub_klines.py` owns daily K-line and minute K-line fetching, cache reuse only when fresh cached rows cover the requested limit, provider attempts through `ProviderRuntime`, invalid provider-row filtering followed by parsed date/time sorting and latest-window selection, best-effort cache persistence after provider success, bounded provider-call limits that ignore malformed runtime max-limit settings, missing-capability failure recording, cancellation propagation, empty-response failure handling, fallback cache tagging, unregistered-provider skip behavior without writing provider status noise, and minute interval validation. A true stock-level coverage miss remains a stock outcome; when every configured daily provider is temporarily blocked, the coordinator raises typed `ProviderChainUnavailable` with a bounded recovery hint so batch orchestration cannot misclassify a system outage as many missing stocks. Invalid runtime state cannot mask a valid bundle. Implicit automatic recovery starts one daemon background coordinator and returns immediately with the current trusted/closed decision; the coordinator uses the one-in-flight provider gate and 15-second wait bound, atomically replaces runtime, then clears the calendar cache. ## 7. Data Quality Design

Data-quality scoring is intentionally split by reason for change:

- `app/services/data_quality_components.py` owns quote-source/cache, quote-field, K-line requirement, freshness, and cross-source consistency scoring components. Quote fallback decisions should prefer `Quote.from_cache` and `Quote.fallback_used` while preserving source-string compatibility for old cached rows. Quote-field checks first reject non-finite, negative, or zero critical values before any derived interval or change-percent diagnostics, then apply stricter high/low and change-percent boundaries so malformed bases do not produce misleading mismatch notes.
- `app/services/data_quality.py` assembles the public `DataQuality` object and keeps backward-compatible quality helper exports.
- `app/services/data_quality_time.py` owns Shanghai-time quote timestamp parsing, the shared quote/minute market-event freshness matrix, expected quote dates, the 15:15 daily publish boundary, and trading-day gaps. Morning/live rows have a bounded delay; the lunch break requires an 11:25-11:30 snapshot; 13:00-13:15 accepts that snapshot or fresh afternoon data; later afternoon checks require fresh afternoon data; and after close accepts same-trading-day events at or after 14:55, including provider-stamped after-hours updates that are not later than the check time. Weekend/holiday checks use the previous trading day's closing snapshot.
- `app/services/data_quality_kline.py` owns K-line source/date/cache/fallback assessment and uses the same `latest_expected_daily_kline_date()` policy as actual cache reuse. It selects the latest parsable K-line date and its source instead of trusting the input tail, so unsorted rows, malformed trailing rows, or stale/demo tail rows cannot hide a fresher row or mislabel the source. K-line level selection and score penalties are ordered rule tables so stale-data thresholds, fallback-cache penalties, and demo-source penalties can be tuned without changing assessment assembly. Short-cache, normal-cache, and fallback-cache wording stays distinct, and a completely missing K-line set emits only the missing-data note instead of duplicating it with an insufficient-count note.
- Cross-source consistency penalties are clamped so malformed comparisons cannot become negative penalties that accidentally add score. If an anomaly-level consistency result has no source notes, the component adds a stable anomaly note for downstream display.
- `app/services/analysis.py` computes technical signals from filtered valid K-lines while data-quality scoring can still inspect the raw input rows. The response `klines` list is filtered before it reaches downstream research modules or the chart.
- Downstream research modules still treat module-specific auxiliary numbers as untrusted. Chip analysis, replay statistics, signal validation, T-strategy wording, and factor/risk adjustments must project non-finite values to explicit fallback, `None`, or `待确认` states before producing user-facing summaries.

Low-quality data must downshift active buy signals, T-plan confidence, and alert triggering.

Optional LLM explanations are allowed to improve wording only after rule output exists. Chat messages contain the current question/topic, symbol/name, deterministic answer, authoritative conclusion/confidence/support/resistance/actions/invalidations, selected quote/indicator facts, at most four data-quality notes, and at most six evidence items. They exclude watchlists, stock notes, alert rules/events, advice history, provider credentials, and other local collections. The request separately carries the configured model and generation parameters plus the LLM API key as transport authentication; the key is never inserted into chat messages.

The first model response must decode as the exact structured shape, preserve every authoritative binding, and pass explanation, action, conclusion, and numeric-grounding checks. Any `LlmOutputValidationError` can trigger one correction request with the same bounded context and a stricter numberless/non-action explanation instruction; the previous raw response is not echoed back. One outer `asyncio.timeout` wraps initial generation, local validation, and the optional correction, so `ASHARE_RADAR_LLM_TIMEOUT_SECONDS` is a shared total budget rather than a fresh allowance per attempt. There is no third attempt, SDK transport retries are disabled, and request failure, total-budget expiry, or a second validation failure returns the deterministic rule answer. Sanitized diagnostics do not echo model output, the question, or credentials.

Advice snapshot, chart-mark, alert-rule, alert-event, and note failures remain non-blocking, but each failed component contributes a sanitized `WorkbenchDataWarning`; raw exception text is limited to diagnostic logs. The frontend shows the bounded warning summary beside source metadata and does not label the core quote connection as fully healthy when local state degraded.
- `app/services/research_replay.py` owns historical signal replay, pattern detection, and replay-pattern statistics. Signals use only the completed signal bar, require a valid positive-volume next-session open for entry, deduct the shared standardized round-trip friction, and de-duplicate the same pattern across each five-day evaluation window. Invalid target bars stay `None`/`待确认`; a latest signal without a subsequent executable open is not fabricated as a trade. Mature success rates use only finite completed returns, and notes disclose the remaining commission, limit-queue, and order-book modeling limits.
- `app/services/research_risk.py` owns risk radar item scoring, levels, and top-risk extraction. Risk radar items are built from ordered rules so trend, valuation, event, liquidity, market, timeframe, risk/reward, and data-quality risks can be tuned independently.
- `app/services/research_risk_reward.py` owns target/stop calculation, finite risk/reward metrics, risk-reward rating, scenario weights, and scenario plans. Public report construction is staged into metric/rating/scenario parts before final response mapping so field rounding and wording stay isolated from domain calculations. `risk-reward-level-availability.v1` exposes `upside_available`, `downside_available`, `ratio_available`, target/stop basis and an availability reason. An upside target requires observed resistance, ATR, or both; a downside stop requires observed support/MA20 structure, ATR, or both. Missing inputs no longer create fixed fallback target/stop levels: compatibility numerics stay zero, summaries render `待确认`, the ratio is withheld and rating stays wait-oriented. Report assembly otherwise cleans non-finite or non-positive inputs, caps abnormal targets, filters stale structural stops and rejects wrong-side levels. Scenario weights are heuristic rule weights, not statistical probabilities; they preserve a neutral path floor and remain capped by rating/validation/timeframe gates.
- `app/services/research_theme.py` owns industry/concept theme context, relative strength, ordered evidence rules, opportunities, risks, and missing-data notes. Theme stats clean industry names, industry change, stock change, concept names, concept ranks, and concept change percentages before scoring or text assembly, so blank concepts or non-finite upstream values do not produce `nan/inf` text or become the strongest concept. Evidence slots are rule helpers so industry, concept, average, and relative-strength explanations keep stable order while wording or thresholds evolve. Concept report output is capped after de-duplication and scoring, so UI payload size stays bounded without truncating the statistics used for score/summary/strongest-concept decisions.
- `app/services/research_timeframe.py` owns short/swing/mid-term timeframe trends, alignment score, and conflict level. Requested 20/60/120-day identities remain fixed, and only windows with complete row coverage participate in alignment or conflict; one complete window cannot be described as multi-period resonance. Timeframe row selection, metric calculation, score components, conflict classification, label selection, and evidence text remain separate.
- `app/services/research_t_strategy.py` owns intraday T strategy style, suitability, low/high zones, and stop conditions. Style and suitability are ordered rule tables so market risk, narrow range, trend rolling, data-quality blocks, tradable range, and validation-risk gates keep explicit priority. Low/high zone and stop-condition wording use explicit `待确认` fallbacks when key price levels are unavailable, while missing resistance can still use price plus volatility buffer rather than collapsing to a false zero zone.
- `app/services/research_validation.py` owns signal validation items, status/confidence scoring, overall validation status, and validation summary. Required price, support, resistance, and moving-average inputs must be finite and positive before an item can leave `等待确认`. Timeframe levels, status labels, overall labels, risk thresholds, volume-confirmation ratio, and defensive groups are centralized constants; status/confidence/overall decisions remain ordered rule tables. The intraday T-range uses a strict open interval and remains a cost-reduction adjustment on existing holdings, not a new-position signal.
- New report domains should be extracted beside `research.py` first, then re-exported from `research.py` only when existing routes or tests need backward-compatible imports.

## 13. Configuration Design

Runtime configuration uses the `ASHARE_RADAR_*` environment namespace. The complete variable table is maintained in [OPERATIONS.md](OPERATIONS.md); this design document records the ownership boundary rather than duplicating every runtime knob.

LLM answers require `ASHARE_RADAR_LLM_API_KEY`, `ASHARE_RADAR_LLM_BASE_URL`, and `ASHARE_RADAR_LLM_MODEL`. Process environment values win; otherwise the shell reader accepts only simple top-level assignments for the five allowlisted `ASHARE_RADAR_LLM_*` names in `$HOME/.zshrc`. The profile is parsed rather than executed, command substitutions and nested shell constructs are ignored, and a profile containing the API key must be a regular current-user-owned file with no group/other permissions. There is no vendor default, project-file, browser, or imported-user-data fallback.

Configuration ownership is split while `app/config.py` remains the stable import facade:

- `app/config_settings.py` owns `Settings`, environment/default resolution, project-relative paths, and the lazy allowlisted shell fallback.
- `app/config_shell.py` owns non-executing shell assignment parsing and secret-file permission checks.
- `app/config_validation.py` owns security-sensitive LLM endpoint normalization and validation.
- `app/config.py` re-exports the compatibility surface and contains no settings implementation.

Provider, scheduler, cache, retention, quality-threshold, reliability-retention, and LLM settings are captured once in `Settings`. Provider credentials and switches are injected by `app/services/provider_registry.py`, so individual provider adapters do not read environment variables directly. Legacy aliases remain accepted where documented for local compatibility, but new settings use `ASHARE_RADAR_*`; LLM settings have no legacy aliases and only the bounded shell-profile fallback described above. Missing optional values use defaults, while present but malformed boolean/numeric values and unsafe LLM URLs fail fast without echoing secret input. Configuration is process-scoped and requires restart after changes.

Python dependencies use three explicit profiles. `requirements.txt` and `requirements-dev.txt` declare runtime and engineering inputs, with complete hashed Python 3.12 resolutions in their matching lock files. `requirements-security.txt` declares only the vulnerability-audit and CycloneDX generators; its matching lock is independently installable with binary distributions and contains no optional market-provider SDK. Reproducible runtime installs use the runtime lock, development and quality CI use the development lock, and the Linux Security job uses the isolated security lock. JavaScript development dependencies are installed from `package-lock.json` with `npm ci`. CI runs `pip check` and verifies generated API/function documents through non-mutating `--check` modes.

## 14. Health, Reliability, and Supply Chain

Health probes have separate operational meanings:

- `GET /api/health` is the backward-compatible summary.
- `GET /api/health/live` is process liveness. It reads settings from application state and deliberately does not resolve the container, SQLite, scheduler, scanner, or providers.
- `GET /api/health/ready` is admission readiness. Startup sets `accepting_requests=false`, flips it only after runtime startup, and resets it before shutdown. The probe then performs a read-only SQLite `SELECT 1` with a 250 ms SQLite busy timeout inside an overall one-second async bound. External provider reachability is not a readiness dependency; a runtime standby can be ready and reports `leader`, `standby`, or `single` separately.
- Probe responses use `Cache-Control: no-store`; failed readiness returns generic component state rather than an exception or local path.

`GET /api/system/reliability` reports project-local SLIs and provisional SLOs from UTC-hour aggregates plus existing terminal run history:

| Indicator | Window | Objective | Minimum evidence |
| --- | ---: | ---: | ---: |
| Workbench usable | 7 days | 99% | 20 requests |
| Workbench data quality at least 50 | 7 days | 95% | 20 requests |
| Workbench quote/K-line freshness | 7 days | 95% | 20 requests |
| Workbench without cache/provider fallback | 7 days | 80% | 20 requests |
| Provider attempt success | 7 days | 95% | 20 attempts |
| Ordinary scheduler task success or degraded completion | 7 days | 95% | 20 tasks |
| Full-market success or degraded completion | 30 days | 90% | 3 terminal runs |
| Full-market ranked / eligible-symbol coverage | 30 days | 95% | 3 terminal runs |
| Full-market non-retry duration p95 | 30 days | at most 90 minutes | 3 durations |

Every item exposes its target and sample floor. Below the floor, status is `insufficient_data`, not `met`. Cancelled tasks/scans do not count as failures; interrupted scans do, and retry durations do not distort the duration SLI. These objectives are initial local operating hypotheses, not an external SLA or evidence of provider availability.

`tools/provider_canary.py` is an optional bounded live-provider contract check. It uses a temporary SQLite database, concurrently probes representative SH/SZ/BJ symbols with non-cached quotes and five-row completed daily-K requests, checks a stock pool containing all three markets, validates identities/timestamps/OHLCV/order, sanitizes errors, and closes DataHub within a bound. Representative market probes use the ordinary provider-call timeout while the larger stock-pool refresh uses its dedicated timeout; one overall deadline still bounds the complete concurrent set. Exit codes distinguish complete (`0`), partial (`2`), and unavailable/cleanup failure (`1`). It is deliberately excluded from required pull-request CI because it uses volatile external systems and may require local provider configuration.

Supply-chain automation is isolated in `.github/workflows/security.yml`. It installs the hashed security-tool profile from wheels, audits the runtime, development, and security-tool Python locks with `pip-audit`, audits the npm graph at high severity, scans the current tree and complete Git history with checksum-verified Gitleaks and fully redacted findings, generates normalized Python/npm CycloneDX SBOMs twice and requires byte equality, and uploads the SBOM artifacts. Keeping audit execution separate from application/provider installation reduces platform-specific build and third-party setup exposure. Dependabot covers pip, npm, and GitHub Actions. Every external action reference is a full commit SHA, and checkout never persists credentials. This provides dependency inventory and recurring detection; it does not currently generate signed release artifacts, build provenance attestations, or claim a SLSA level.

## 15. Known Design Debt

- `app/services/research.py` is now a thin compatibility facade. Keep new research behavior in domain modules and re-export only stable public builders from the facade.
- Frontend JS and CSS are split by surface, with shared render helpers and explicit search-controller composition. Static size/selector-ownership gates and desktop/tablet/mobile browser geometry checks cover the highest-risk market-scan layouts; broader screenshot-diff coverage across every work area remains future debt.
- Pydantic models are now grouped by domain. Keep `app/models/schemas.py` as a compatibility layer, and prefer domain-module imports when touching code for a real change.
- `DataHub` is now a thin orchestration facade for provider flows; quote/kline/metadata/order-book/cache/status/runtime/source-plan helpers have been split.
- Data quality is now split into response assembly, score components, quote-time freshness, and K-line freshness modules. Keep public compatibility imports in `app/services/data_quality.py`.
- SQLite schema code is split into initialization, definitions, and guarded compatibility migrations. Keep `app/db/schema.py` as the stable import surface for cache initialization, keep `app/db/mappers.py` as the stable import surface for legacy row-mapper imports, and keep direct migration helpers safe for partial legacy databases.
- Runtime data is intentionally outside source control. Keep database files, WAL/SHM files, and generated trading calendars under `data/` only as local state.
- Reliability targets are code-defined initial objectives and have no burn-rate alerting or error-budget release policy yet. Revisit them only after representative sample volume exists.
- The repository produces reproducible normalized SBOMs but does not yet sign distributable artifacts or emit/verify SLSA provenance. Do not describe current CI as release attestation.
