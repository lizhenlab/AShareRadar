# 研究数据同步任务完善 Goal

## 可直接交给 ChatGPT / Codex 的目标

完善 AShareRadar 的研究数据同步流程：让用户能够按任务查看真实进度、主动停止长任务，并根据持久化的原始参数和已完成股票只补做未完成项。修复旧任务回执长期禁用同步按钮、市场筛选自动折叠的问题。已保存观察、历史版本和本地密钥保护必须保持；同步仅由显式操作触发。完成正常、失败、重复取消、重启恢复及浏览器回归，同步代码与文档，通过现有工程门槛后交付可运行结果。

状态：已完成（2026-09-10，Asia/Shanghai）。已建立并执行原生 Goal；修改前已备份当前可提交源码，包含此前未提交修改，不包含业务数据库或密钥。

## 本轮修改方案

1. **可靠的任务记录。** 保存规范化请求、已完成股票和父任务身份；每项观察与对应进度在同一事务中提交。增加按任务ID查询和显式重试未完成项，重试创建新任务，不重取原任务已成功股票。同一父任务的重复补做返回既有子任务；需再补做时操作该子任务。旧记录缺少原始参数时明确不可直接重试，不解析错误文本猜参数。
2. **可停止的长任务。** 页面增加停止入口，立即显示正在停止；后台在下载块和Parquet批次之间协作退出，等待已拥有的写入、线程和暂存文件收尾后才释放任务槽。重复停止幂等，已发布历史版本保持可读，不把正在停止伪装为已取消。
3. **真实阶段进度。** 显示签名、下载、校验、归并和写出阶段，以及已知的字节数或行数；未知总量不制造百分比。进度更新有节流和终态保护，普通GET不采集供应商数据。
4. **前端状态收敛。** 任务不在最近列表时按ID核实，防止旧成功回执永久占用页面；保留提交前后请求的身份顺序。市场筛选、刷新保持展开状态，正常导航和明确写操作各自拥有生命周期。

## 验收条件

- 用临时数据库、假提供者和真实Parquet建立修前反例；观察与checkpoint同时成功或同时回滚，重试精确选中未完成股票。
- 覆盖启动前、下载中、校验中及写入中的停止，重复取消、停止与完成竞争、重启恢复、旧任务参数缺失和查询404。
- 验证浏览器按钮、任务进度、未知回执收敛、筛选展开状态及跨浏览器布局，不为了通过测试放宽请求或完整性约束。
- Python函数与类型门槛、app/tools综合覆盖率90%、相关浏览器、参考文档和秘密隔离检查均通过；无需新增运行依赖。
- API Key继续只保存在Git忽略的本地受限文件中，不写入源码、测试、浏览器或Git。真实账号不用于压力测试。

## 后续独立候选

财报年报/季度目前按最后一份观察读取，可能隐藏此前已缓存期间；后续应按完整期间观察保留并显示各自获取时间。数据新鲜度摘要也需区分供应商数据日期与本地获取时间。本轮先完成任务控制闭环，不据这些候选新增未经核实的评分或自动采集。
