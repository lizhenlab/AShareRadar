# 概率数值边界与受检读取优化 Goal

状态：本轮已完成（2026-09-23，Asia/Shanghai）。原生 Goal 与本文件使用同一验收范围。

## 可直接交给 ChatGPT / Codex 的目标

将概率数值估计从编排和证据验证中解耦；对完整概率查询实测定位重复工作，优化受检扫描读取。保持确定性数值、评分版本、API、规范摘要、严格 JSON、同一 SQLite 快照及取消门禁。迁移全部真实消费者，同步类型和工程文档，以固定输入输出、篡改/并发回归、只读基准和服务重启验收。保留既有未提交工作、运行数据与冻结试验，不新建试验、不请求真实供应商或推送 GitHub。

## 验收边界

- 每次受检请求仍完整读取、严格解码并验证摘要；不采用跨请求可信缓存，不以只读连接或本地文件时间替代内容验证。
- 时间检查先于外部观察器；回调在最终摘要失败前可能已见到部分行，但失败绝不能产生受检会话或评分合同。
- publication 的完成、更新、封印时序及每条结果时间仍检查；旧 backfill 只保留原审计读取能力。
- 概率模型版本、拟合顺序、边界取值、不收敛异常与完整证据不变；本轮不宣称预测精度或收益提高。
- 基准使用同一封存批次和相同日历等依赖，逐次核对原摘要、动作资格和评分合同。报告真实测试范围，不以相关回归替代全量覆盖率。
- 原前瞻计划的 source_drift 保持，创建或切换新试验仍需此前单独确认。

## 完成结果

三项修改已落实。纯数值估计器与共享值校验独立，主概率模块3,793→3,517行；完整快照的时间验证及评分合同汇总并入现有规范行遍历，删除重复查询，写入预检和完整性门禁保留。

同机69,794字节固定结果逐字节一致；持久测试保留精确业务合同、窄浮点容差和完整摘要回放，避免跨数值库误报。25模块1,188项相关回归、Ruff、Mypy463源文件、编译/Pyflakes、JS语法、仓库与索引检查通过。未重跑全量覆盖率或浏览器测试。

相同封存批次与运行日历下，两版各5次交替只读基准，中位受检读取3.224→2.977秒，约减少7.65%；摘要、资格和评分合同均一致。严格完整校验仍需约3秒，后续性能工作应继续实测JSON解码、证据回放和响应构造，不能用跨请求信任缓存掩盖。概率证据编排和执行准入仍可进一步按各自合同拆分，本轮未将数值边界拆分视为整个研究模块已经简化完毕。

服务已平滑重启并通过ready，预热后接口除联合执行诊断时间外与原响应一致，概率继续等待标签、历史参考不可用；扶摇请求0→0。旧试验保持source_drift及原收据，未改策略或新建试验。详细方法、局限与证据见[当前验收](TEST_PLAN.md#6-当前验收结果)。
