# 项目维护重构 Goal

## 可直接交给 ChatGPT / Codex 的目标

系统审计本仓库全部自有代码、测试、CLI、静态资源、配置和工程文档。先建立文件与生产入口依赖清单，核实动态加载、路由、调度、离线 CLI 及持久化消费者。删除无现行用途的函数、重导出、模块、旧兼容分支和历史实施文档；将消费者迁移到唯一所属实现，合并重复行为并明确生命周期。保留当前有效功能、真实用户数据以及现存数据仍需要的完整性检查，不以文件名或版本号判断废弃。

工程文档只保留当前功能、架构、操作、维护、研究工具和测试约定。研究夹具与运行产物分离，运行时不能从文档目录回退读取样本。新增仓库一致性检查，持续阻止无效内部导入和断开的本地文档链接。

执行前保存可恢复工作区快照；用户已经授权删除无用源码和文档，无需逐项询问。保留风险与行为测试，删除只为旧名称存在的恒等测试。全部源码冻结后运行完整 Python 回归、原有 90% 覆盖率门槛、Ruff、显式 Mypy、函数复杂度、JavaScript/运行环境/依赖/文档检查，以及受影响的真实浏览器回归。只有依赖闭合且验收完成后才将 Goal 标记 complete。

## 审计范围与删除原则

初始盘点覆盖 823 个 Python 文件（app 482、tools 32、tests 309）和 94 个可从实际 HTML 入口到达的前端 JS 模块。301 个零名称引用候选逐类过滤装饰器、Pydantic/AST 回调、MRO、字符串及持久化消费者，不能将该候选数当作死代码数。

移除的兼容接口以实际导入迁移和行为回归为依据。仍在使用的旧扫描摘要、数据库迁移、来源记录读取及当前实验模型属于有效契约；保留不等于保留历史实现副本。静态可达性检查能排除许多残留，但不证明外部 SDK、实时行情或研究收益有效。

## 本轮结果

- 删除 15 个旧聚合/转发模块，所有消费者迁到实际实现；清理死函数、空钩子、测试专用包装和重复服务属性。
- 跨模块私有依赖从 298 降到 269，类型应用文件下限保持 323；前端主入口从 3099 行降到 2791 行。
- 文档从 43 份收敛为 12 份 Markdown。旧研究目录清空前，将仍被当前功能使用的静态基线及测试夹具分别迁入应用资源和测试目录；运行时代码不再读取文档研究目录。
- 新增 `tools/check_repository.py` 并接入 npm/CI，持续检查内部导入和本地文档链接。
- 完整验证：6292 项 Python 测试、68 个子测试通过，覆盖率 90.71%；四浏览器矩阵 167 项通过、49 项按现有项目条件跳过。正式 v5 评分规格摘要不变。

完整当前结果记录在[测试计划](TEST_PLAN.md)，不新增按日期堆叠的历史实施目录。当前扫描持久化适配出口仍复用评分服务实现，现存数据格式校验继续保留；这两项有现行消费者，不属于本轮删除的失效兼容层。
