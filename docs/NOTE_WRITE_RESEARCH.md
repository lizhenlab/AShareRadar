# 笔记条件写入与离线创建：研究和实施方案

核对截止：2026-09-09。范围为单机个股笔记的并发编辑、草稿恢复与外部行情不可用时的本地创建。四篇原始论文包含 2026 年正式工作坊研究与更贴近问题的 2025 年论文；正文区分方法、案例、实验和局限，注明实际阅读版本及正式发表身份。未运行作者系统或复现其结果。

最值得落实的两条原则：**以用户编辑时观察到的记录作为写入前提；把已提交内容、用户未提交草稿和派生展示状态分别处理。** 本项目只有本地服务后的一个 SQLite 权威库，多浏览器标签不等于多主副本。解除无必要的行情依赖，也不等于增加浏览器离线同步。

## 1. Semantic Conflict Model for Collaborative Data Structures

Georgii Semenov、Vitaly Aksenov。PaPoC 2026 正式短文，非 EuroSys 主会论文；ACM proceedings 2026-04-26 发布、工作坊 04-27，pp.25–31，DOI 10.1145/3806077.3806700。[官方目录](https://doi.org/10.1145/3806077)、[官方议程](https://papoc-workshop.github.io/2026/program.html)。实际读 [arXiv v1，2026-02-22](https://arxiv.org/html/2602.19231v1)：§2–4、§6。ACM 正式正文访问失败；v1 含占位 DOI/ISBN/received 日期，不能把这些模板值作为发表信息，也不声称其与终稿相同。

**论文事实。** 给操作记录前提，用 entails/discards 关系识别语义冲突，再以新协调操作重接历史。日历例子展示不同字段也可能有相互依赖。结果是定义、例子和证明草图；§3.4 的收敛依赖停止新增、全部冲突解决，第二部分还假定集中式协调，不能说任意离线执行自动正确收敛。

**本地判断。** 保留冲突供用户决定比任意后写覆盖更适合研究笔记。当前不需要复制日志、语义合并器或 LLM 改写；核对整行原始表示是一种刻意保守且可测试的前提检查。

## 2. Grove: A Bidirectionally Typed Collaborative Structure Editor Calculus

Michael D. Adams、Eric Griffis、Thomas J. Porter、Sundara Vishnu Satish、Eric Zhao、Cyrus Omar。POPL 2025，PACMPL 9，Article 73，2025-01，29页，DOI 10.1145/3704909。阅读[作者提供的正式排版全文](https://hazel.org/papers/grove-popl25.pdf) §2.4、§3.4、§4、§6.3–7。

**论文事实。** 捕获编辑动作，使用带身份的图节点/边及可交换补丁；未解决冲突仍显式存在于可检查的编辑状态中。给出 Agda 元理论与 OCaml/网页演示。它没有证明普通笔记的合并符合用户意图；网络、交互及字符串序列整合仍有后续工作，不是用户恢复成功率实验。

**本地判断。** 借鉴“冲突可见且草稿可继续处理”，不把后到达视为更正确。已有纯文本表单用版本冲突反馈即可，不宜改成图编辑器；提交身份检查也不能代替前端草稿所有权。

## 3. Denicek: Computational Substrate for Document-Oriented End-User Programming

Tomas Petricek、Jonathan Edwards。UIST 2025 正式论文，会议 2025-09-28 至 10-01，19页，DOI 10.1145/3746059.3747646。阅读[作者会议版全文](https://tomasp.net/academic/papers/denicek/uist-2025.pdf) §4.2、§5.1/5.5–5.7、§6、§7.3–8。

**论文事实。** 以编辑历史构造文档，复用合并/冲突检测实现离线变体和派生计算失效。评估是六个形成性例子、Webnicek/Datnicek 案例及定性/启发式分析。合并不对称且会多报冲突；原型缺合适的冲突界面，数千行使用已笨重，没有扩展性验证。

**本地判断。** 用户笔记与行情、图表等派生读取应分开确认；读取失败不应否定已提交的笔记。可采用这条边界，但不将 SQLite 全面改成编辑日志，也不把原型案例当作性能收益或真实离线体验的保证。

## 4. Demonstration of ProvSQL Update Provenance through Temporal Databases

Albert Ariel Widiaatmaja、Belkis Djeffal、Ashish Dandekar、Pierre Senellart。ProvenanceWeek 2025 同行评审演示论文；会议 2025-06-22 至 27，[ACM 记录](https://doi.org/10.1145/3736229.3736253)发布日期为 2025-09-02、pp.71–76。实际读[作者提供的5页稿](https://pierre.senellart.com/publications/widiaatmaja2025demonstration.pdf) §3.1–3.4、§4；其页数与目录不同，未冒称逐字等同终稿。[官方录用分类](https://ucdbg.github.io/ProvenanceWeek2025/acceptedpapers)。

**论文事实。** PostgreSQL 触发器保留旧/新元组、操作 token 与时间等元数据，以溯源电路实现历史查询和撤销。证据是操作示例及 Wikidata 任职历史演示；不是并发、故障恢复或空间开销基准。删除仍保留元组，这与直接删除的产品合同不同。

**本地判断。** 条件令牌能防覆盖不同当前内容，却不保存过去版本、不等于完整审计历史。当前不移植半环、PostgreSQL 或永久软删除。若以后增加研究历史，须另定保留、删除、导入和来源含义。

## 原始工程依据：不冒称新论文

[SQLite 官方隔离说明](https://sqlite.org/isolation.html)说明写事务被串行化，WAL 读者持有事务快照。本地推导：浏览器早前 GET 已结束，再发 PATCH 是另一个事务，单写者不能知道用户依据了旧内容。应在短写事务内核对客户端观察到的表示；不能把锁跨过人的编辑时间。

[RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)规定 If-Match 强比较，用来避免丢失更新；不满足时不执行方法，标准状态为 412。本项目选择请求体令牌与 409 是自定义应用合同，不应声称实现了 If-Match/412。响应丢失也不证明服务端未提交；没有操作去重身份时不能擅自保证重试恰好一次。

## 与当前已选方案的准确映射

下列为本项目工程设计；实际实现的验收结果见[测试计划](TEST_PLAN.md)，论文不替代这些验证：

1. 条件令牌取**全部原始持久列及值类型**的 SHA256，包含 id、股票身份、created_at、updated_at 和 visible；在 BEGIN IMMEDIATE 内核对后写入。不新增 revision 列，不把墙钟当版本，也不表示历史修改次数。
2. 恢复后原始表示完全相同，可接受旧令牌：这时不会覆盖一个不同的当前记录。只要内容、身份、时间、可见性或值类型不同，就应冲突。本轮不为“曾发生过别的历史”额外增加恢复代次。
3. 冲突后保留用户草稿并允许明确重新读取/比较；不能自动拿新令牌重发旧草稿，否则绕过保护。隐藏和删除也是写入，同样要绑定所观察记录。服务端已成功而后续列表读取失败，应保留提交确认；迟到回执不能覆盖另一个表单的新输入。
4. “离线”指本地服务和 SQLite 可用、外部行情不可用。仅明确 price/date 与可信本地股票身份齐全时跳过 provider；缺省字段沿用原报价含义。不伪造现价、Quote 或来源，不声称浏览器与本地服务断开仍会自动排队同步。
5. 先验证同字段编辑、编辑与隐藏/删除交错、同一表示恢复/不同表示冲突、显式空值、提交后读失败与再次人工保存；再验证显式价格日期的本地创建零 provider、缺省路径仍请求行情。以实际公开接口、临时 SQLite、多标签交互复现为准，不用论文代替验收。

**不采纳项。** 不采用 CRDT/OT、自动语义合并、LLM 冲突处理、新同步服务、完整事件溯源数据库。它们解决的多副本合并或可重放历史问题，比本轮两个已选写入边界更大。本次有界检索没有找到已充分实测并能直接证明单 SQLite 服务/多标签方案的 2026 研究；因此选择这一篇 2026 工作与三篇更相关的 2025 论文，没有用关联弱的预印本凑到五篇。



## 可执行修改与验收

| 优先级 | 受控反例 | 实施方案 | 完成判据 |
| --- | --- | --- | --- |
| P1 | 两页读取相同笔记，后保存的旧内容静默覆盖先提交的新内容；更新时钟相同仍发生 | 返回完整持久表示摘要；更新、显隐、删除在短写事务内检查客户端原摘要 | 第一个提交成功，旧状态提交 409；缺失/非法令牌 422，不存在 404；并发独立连接、空 PATCH、创建/更新回执映射及写事务提交异常回滚均验证 |
| P1 | 保存等待期间的新草稿被回执/列表重绘清掉，原控件也失去所有权 | 复用仍属于同股票、同笔记的编辑表单；成功回执只推进自己提交的基线；409 后只读展示最新内容，再由明确操作选择继续编辑方式 | 同笔记继续输入、另一笔记草稿、裸代码/规范代码、迟到回复、列表失败与移出当前列表边界通过实际浏览器验证；查询不自动重试写入 |
| P2 | 临时库已有正确股票身份，显式价格和日期的笔记仍因行情失败返回 503 | 单独准备身份及默认字段；仅两个字段明确且本地精确身份可验证时跳过报价 | 原反例 503→200、provider 调用 1→0；缺省字段、未知/过期/错配身份继续原报价路径；无合成行情且插入失败不留半条数据 |

默认字段不是无意义的空值：原创建接口用当前报价补价格和时间。本次只解除已显式提供这些字段时的多余依赖；本地股票池仍采用既有 30 天回退范围，冲突别名、空名称、占位名称及市场错配不能凭行顺序挑一个。超过范围后返回原行情路径，既不把过期价格当现价，也不接受请求方提交任意名称。

摘要包括值类型，避免 SQLite 旧坏值经显示兜底后变成相同内容而绕过检查。它是状态前提，不是授权凭证、修改次数或不可篡改历史。把快照比较放进 `BEGIN IMMEDIATE`，让比较与写入不可被另一写事务插入；只在 API 提前比较或只使用进程锁都不足以保证这个条件。

这是保守的整行冲突：另一页只改可见性也会使原文本编辑冲突。对于当前低频、少字段的研究笔记，明确展示冲突比静默拼接两份意图更容易维护与验证。待真实使用出现过多无关字段冲突，再设计字段级前提；不能仅因论文提供合并方法就增加复杂度。

完整单条读取接口让移出首页的笔记仍可核对，但不等于已实现历史分页。响应丢失后，条件写可能得到冲突或不存在；当前没有创建操作幂等键，也不宣称网络不确定下恰好一次。保留草稿的范围是当前页面仍打开的编辑表单；显式取消或切换到另一个编辑器沿用原 reset 语义。它不是浏览器崩溃恢复或多机同步。

## 后续优先级

1. 完整笔记历史分页：明确排序、总量、分页中更新时的稳定性、空页和续页失败恢复；当前只增加按 ID 精确读取。
2. 创建请求的重复提交防护：先定义操作身份、重试窗口和导入后身份含义，再实现幂等回执；不靠内容相同就合并两次有意创建。
3. 若引入笔记历史/问答，另定旧版本可见性、删除、来源和当时已知内容；当前摘要不能替代历史账本。
