# 前瞻恢复与整套备份实施设计

本文区分已交付的诊断、离线归档能力与尚待完成的真实采集和运行恢复验收，不改变研究准入、既有主库备份或清理策略。旧计划、收据、快照和封存运行目录保持不可变；新增归档工具不登记新计划、不启动扫描、不下载供应商资料。

2026-10-15已实现来源新鲜度和明确阻断条件、runner独立健康记录及离线检查、只读容量统计与范围预览，以及显式根驱动的离线归档创建、验证和新目录恢复。入口见[前瞻采集](STRATEGY_PROSPECTIVE_COLLECTION.md)、[容量与备份范围](WORKSPACE_STORAGE.md)和[工作区离线归档](WORKSPACE_BACKUP.md)。这些工程能力不能代替合格生产输入、真实采集验收或实际运行恢复演练。

## 1. 前瞻恢复：先确认能产生合格输入，再登记未来计划

2026-10-15只读核对中，rev2仅有一张`source_incomplete`收据，合格篮子为0，10月14日锚点逾期。`prepared-20261008`运行目录完整性通过，但它与旧rev2源码合同不匹配。健康运行目录不等于旧研究已恢复；已错过的锚点不能补登记。

### 文件与职责

| 归属 | 当前能力与后续边界 |
| --- | --- |
| `app/services/strategy_prospective_readiness.py`及`strategy_prospective_freshness.py` | 已分离来源完整性与新鲜度，给出期望交易日及待满足条件；日历覆盖不足返回未知，不联网猜测。范围限输入和计划身份，运行依赖由独立inspect验证 |
| `tools/strategy_prospective_runtime.py` | 继续独立验证源码、依赖和配置；返回运行目录摘要供显式身份绑定，不重写旧计划 |
| `app/services/strategy_prospective_health.py`及`tools/run_strategy_prospective.py` | 已增加独立原子健康记录与会话锁；保留最后完成时间、下一检查时间、身份及未解决故障，业务通知规则不变 |
| `tools/inspect_strategy_prospective_runtime.py` | 已只读核对指定运行目录、计划、控制绑定与健康期限；返回结构化状态及退出码，不触发扫描或采集 |
| 生产数据准入所属模块 | 针对日K滞后、单一价格的未知状态补充可追溯证据；仅影响后续真实批次，不能把旧`missing`改成`skipped` |

健康记录不是研究证据，也不进入收据链；文件有界、原子替换，失败不能伪造成功时间。使用操作系统进程托管负责启动/重启，独立只读检查负责发现失联；正常等待不产生重复通知。不能仅通过PID或日志有无输出认定采集成功。

### 实施与验收

1. 对新批次输出逐项准入结果与缺失分类；保持第一批不合格不回退、完整股票池和PIT要求。用固定夹具覆盖完整、缺失、来源过旧三类状态，诊断前后数据库与研究文件内容不变。
2. 为runner补健康记录与离线检查；模拟正常等待、服务不可达、突然退出、时钟回退及恢复。必须识别过期心跳，不能重复提交已预占的当日扫描，不能将健康检查写入当时采集证据。
3. 固定实现及资源后，在受检运行目录中为**尚未到来的**区间登记新计划。明确模板、日期轴、日历覆盖、资金、截止时间及源码摘要；不与旧rev2拼接宣称同一试验。变更实现后重新核验，不修改旧摘要。
4. 新计划启动前确认有可合格的生产输入、独立控制目录绑定、恢复演练及正式资料获取方案。启动后以首个真实`captured`收据和归档重放成功作为采集验收，不能以watch进程启动代替。
5. 后续单独实现到期驱动的`evidence/evaluate`：以收据头、资料版本与成熟日期去重，保持缺失锚点。正式材料、连续资金/持仓与前瞻统计未通过前，采用资格继续关闭。

第1、2项的离线诊断与健康能力已实现；新批次的真实输入资格仍须实际验证。下一步是明确未来计划参数、正式数据来源及托管方式，固定新的受检副本，再推进第3至5项。冻结研究的既有运行目录不接收这些更新。

## 2. 整套备份与容量：明确可恢复对象和一致性边界

现有`app/services/runtime_backup.py`继续拥有SQLite备份与原位恢复。工作区归档采用独立格式，只覆盖操作者明确声明的根和数据库；不能把主库备份改称为全部数据备份，也不能将整个项目递归压缩后宣称运行状态已完整保存。

### 清单与接口

| 当前归属 | 接口与职责 |
| --- | --- |
| `app/models/workspace_backup.py` | 已实现版本化scope及manifest：显式逻辑根、原源绝对路径、归档相对路径、大小、普通权限、SHA-256、创建时间、数据库快照清单、排除项与保守一致性声明 |
| `app/models/workspace_storage.py`及`app/services/workspace_storage.py` | 已实现`inspect_workspace_storage(roots, budget)`；按显式根分类统计，返回字节数、文件数、观察窗口及未完成原因，不读取文件内容 |
| `app/services/workspace_backup.py`及同域I/O、scope、manifest、SQLite、domain模块 | 已实现创建、验证与新目录恢复；逐库快照、稳定文件复制、清单验证和已知领域绑定检查分开负责，验证无需原源路径 |
| `tools/workspace_storage.py` | 已实现`inventory`和`preview`命令，通过`--scope`指定清单，输出声明范围、容量、排除项及尚未满足的一致性要求；不创建备份 |
| `tools/workspace_backup.py` | 已提供`create/verify/restore`；使用独立scope，要求恰好一个主库及范围内全部SQLite，目的目录必须尚不存在；支持预算及外部期望摘要 |
| `app/api/routes/workspace_maintenance.py`和系统维护页面 | 2026-10-16接入显式配置的分类容量、备份覆盖与历史验证记录、runner健康状态；容量手动触发、有界检查；历史回执不替代当前归档验证 |

可选覆盖对象包括主SQLite、`cache_path.with_suffix('.fuyao')`下的研究SQLite和历史文件、关联行情文件、研究产物、计划、收据、原始输入归档及封存运行目录，但不会自动发现这些根。备份scope与容量scope不同，目录根不可重叠；主库和所有旁库都须单独声明。主库内已有行情缓存随数据库快照保留，声明数据库的WAL等侧文件由快照过程处理。

默认按明确名称与后缀排除秘密配置、日志、锁、嵌套备份和普通生产虚拟环境；缓存只匹配`__pycache__/.pytest_cache/.mypy_cache/.ruff_cache`四个目录名，不读取内容识别所有秘密。实际排除进入manifest。runtime保留普通依赖和缓存，但命中秘密等排除时整次归档失败，不能缺件后宣称运行目录完整。共享基础Python等未包含依赖单独报告，归档检查不执行封存Python，也不验证其实际可运行性。

容量统计不加载大文件内容，不跟随符号链接，不把同一文件的硬链接重复计为实际占用；区分逻辑字节与磁盘占用。为文件数、深度与耗时设预算，超限返回`partial`，不能返回完整总量。默认不删除文件、不更改保留规则。

### 一致性与恢复验收

已实现的创建流程要求操作者先停止应用、独立runner、资料同步和清理等全部写入者，并显式声明`offline_writers_stopped=true`。工具取得已知应用、产物及领域锁和声明数据库的SQLite写保留，逐库使用backup API，再复查源文件身份；它不能证明所有外部写入者均已静止。因此结果保持`cross_domain_consistency_verified=false`，不能以mtime检查或存在租约替代跨库、跨目录原子快照证明。

1. 归档目标独占创建，内容放在`payload/<root-name>/`；全部创建与复制使用有界路径和I/O检查，现有目标即使为空也拒绝覆盖。完成清单通过原子独占发布形成标记；有效性仍须实际运行`verify`。
2. 异常和取消只清理本次拥有且身份可确认的对象，不能误删并发替换后的其他目录。强制终止、断电或清理失败可能留下目录；没有清单的目录属于未完成归档，有清单也不能免除校验。
3. 验证只访问归档，检查成员完整性、声明SQLite及已知排名引用、前瞻收据/快照、扶摇当前版本和runtime文件清单。清单自摘要不是签名，外部保存的`--expected-digest`用于固定预期归档身份，不能仅依赖包内自摘要建立来源信任。
4. 恢复到全新目录后，只有主库副本旋转预警流身份，旁库字节保持；输入备份不变，恢复清单生成新的digest并引用源digest。原绝对路径不重写，研究和控制绑定仍需分别处理。`resume_eligible=false`始终保留，不自动启动服务或runner。
5. 工程验收使用临时数据库与文件，覆盖原源不存在时的验证/恢复、损坏和缺失成员、未声明SQLite、路径替换、预算、取消和拒绝覆盖；这些夹具结果不等于对用户真实工作区完成了停机备份或运行恢复验收。

容量清单与范围预览继续保持只读；路径替换、重复inode冲突、无法读取或预算不足报告`partial`。2026-10-16已完成34根、11库的真实备份与新目录恢复演练，本机报告位于`data/local-backups/production-drill-20261016-111145/REPORT.md`；封存运行目录不在本次覆盖内，未证明恢复副本实际可运行。同日新增[维护API和页面](WORKSPACE_MAINTENANCE.md)，并缩短创建时的源租约持有范围：复制和源复查完成即释放，目标完整验证通过后才发布清单；旁库恢复去掉一次确定重复的目标校验，并加入可选阶段进度。

运行环境可用性、原绝对引用重新绑定、前瞻计划继续资格及在线跨域快照协调仍须独立验收，不能从归档成功推断已经完成。历史演练报告记录当时状态，不改写为新实现的性能测量。
