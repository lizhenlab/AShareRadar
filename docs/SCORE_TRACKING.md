# 冻结评分的后续表现跟踪

此功能回答“同一天的高分股票，后续表现是否优于低分股票”。它评估已经保存的全市场扫描原始排名分，不重算历史分数，不评价个股因子总分，也不把评分映射为上涨概率。

## 使用

```bash
.venv/bin/python tools/track_market_scan_scores.py \
  --database data/ashare_radar.sqlite3 \
  --output-directory data/research/score_tracking
```

默认跟踪正式收盘扫描的 D+1、D+5、D+20。命令输出 JSON 和可直接打开的 HTML 文件路径；HTML 无外部脚本或网络依赖，包含版本分组、同日高低分差、覆盖率、逐日到期状态及失败批次。数据库只读，不调用提供者、不拟合模型。更新本地日线后重新运行同一命令即可生成新的观察报告；本功能没有自动行情同步、定时刷新或在线模型晋级。

可用 `--run-id` 指定批次（可重复），用 `--mode` 查看盘中/盘前研究，用 `--as-of` 指定不晚于当前时刻的观察截止。截止时间只限制可见交易日，并不把可覆盖的日线缓存变成当时不可变的数据版本；历史重跑仍是诊断。正式评分版本和数据范围不同的报告不能直接拼接成绩。

输出使用内容摘要命名，已生成文件不会被原地覆盖。研究报告放在被 Git 忽略的本地目录；不能用该报告替代已有概率产物、发布收据或执行证据。

## 比较口径

1. **先选批次。** 同一模式、股票池、规则版本和信号日期使用最早发布的批次，校验冻结摘要。首批损坏会明确列出失败，不事后换成后来的好批次。评分规格指纹不同的有效样本分别统计，未知身份不合并积累有效性证据。
2. **先固定分组。** 使用当时冻结的原始分数选高低各20%；边界同分全部保留，不按股票代码拆分。两端重叠、分数没有差异、成员重复等情况显示不可比较。缺后续行情不会重新分组或补进别的股票。
3. **固定交易日目标。** 以可信交易日历确定 D+H，不用“有数据的下一根K线”代替。按现有上海时间15:15日线发布截点确认完成，目标交易日尚未完成为待到期；已到期但目标或中间日线不完整为缺失。日历无法确定长期目标时单独显示不可用，不抹掉可验证的短周期，也不当作已到期。价格口径与冻结信号不相容、窗口混用不同数据版本或明确发生公司行动时不计算收益。
4. **同日配对、日期等权。** 两组都达到95%结果覆盖率才计算该日的高低分差；汇总仅使用相同的配对日期，每日权重相同。股票数量多或同日反复扫描不能替代更多观察日期。
5. **充分性单独披露。** 区间估计要求至少 `max(20, 2×H)` 个配对交易日、各组至少30条有效结果。成熟样本缺失或扫描日期断档时不压缩时间轴生成区间。区间描述已观察样本的日期区块重采样结果，不是未来收益保证，也不解决重复试验后的择优问题。

回报是冻结报价至固定目标收盘价的毛变化，高低差以百分点展示。它不含手续费、滑点、持仓资金、涨跌停成交约束或做空可行性；高低差为正也不能等同于可执行策略赚钱。已提前留档、已看过的历史诊断、独立样本外验证分别说明，不由单个统计状态自动授予资格。

## 对原评估逻辑的修正

`market_scan_evaluation.py` 原有排名段与十分位比较，各组可能分别使用不同日期的有效收益，从而把行情环境差异误读成评分单调性。现在先按冻结成员检查每个组的覆盖率，再用所有组共同可用的日期计算均值；没有共同日期时，`monotonic` 为不可用，增加比较依据和排除日期数。已有评分、排名和冻结数据库不修改。

实现入口：`market_scan_score_tracking.py` 负责跟踪诊断及冻结扫描、有界日线的只读编排；`market_scan_evaluation_source.py`提供评估与跟踪共用的只读连接、冻结分值、评分合同和PIT摘要读取。`market_scan_evaluation.py`保留公开跟踪入口的导出，`tools/track_market_scan_scores.py`负责输出，`tools/score_tracking_report.py`负责静态报告。2026-09-19按职责拆分，报告口径保持不变。相关回归见[测试计划](TEST_PLAN.md)。
